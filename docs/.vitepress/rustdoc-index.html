Blueberries VOI — Rust API

Generated rustdoc reference for the project's shared Rust kernel and its two host bindings.

Blueberries VOI is a value-of-information study asking how much a grocery store's profit changes when it can see more about the true freshness of the blueberries on its shelf, not just how old they are. The compute that answers that question — shelf physics, a particle filter, and an ordering policy — is written once, in Rust, and reused everywhere the project needs it: in Python notebooks and the CLI, and in the in-browser "studio" that runs the same simulation live. This is the generated API reference for that Rust code, produced straight from each crate's own /// doc comments.

For the narrative version — why the model is built this way, what each observation "rung" actually sees, and what the experiment currently finds — see the project documentation site, in particular its Rust API overview page.

The three crates

voi_core

The shared kernel: shelf physics (aging, spoilage, demand), the particle filter that turns a store's observations into a belief about what's on the shelf, and the ordering policy that acts on it. Everything else in the project calls into this crate rather than reimplementing any of it.

Open voi_core docs

voi_py (compiles to blueberries_voi._core)

PyO3 bindings that expose voi_core to Python as a native extension module. Python notebooks, the CLI, and the pytest suite all reach the kernel through this door.

Open voi_py docs

voi_wasm

A wasm-bindgen binding that compiles the same kernel to WebAssembly. The in-browser studio (a React + D3 app) loads it and drives it with the same JSON RPC contract the native build uses.
