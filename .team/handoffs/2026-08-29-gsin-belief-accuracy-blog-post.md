## 2. The GSIN bug hunt

Looking at the factorial scatter, Oliver noticed GSIN usually looked *worse* than UPC on belief accuracy — counter to the model's designed guarantee that GSIN (lot-resolved scanning) can never be less informative than UPC (pooled scanning). Investigated in two parallel tracks:

**Track A — closed-loop confound (tested directly):** reran the GSIN-vs-UPC comparison with the same shared-order-schedule replay fix used for the ladder chart (one shared order schedule per `(waste, delivery)` context, driven by that context's UPC variant). Result: the gap shrank substantially in most contexts but a real residual survived in 5/6 — confound was a real, partial contributor, not the whole story.

**Track B — code-level bug hunt (background subagent, general-purpose, high effort):** found a genuine, confirmed bug — **`belief_flat_from_unit_bank`** (`crates/voi_core/src/belief_flat.rs:32-61`) truncates the exported belief wire to the newest `L` lot segments, silently dropping older segments with no renormalization. `L` (`l_dim`) was **3** everywhere in the notebook/experiment pipeline (`profit_session_config` in `voi_profit.py`), despite Studio's own compiled default (`DEFAULT_L_DIM` in `params.rs`) already being 10. GSIN and UPC populate the bank very differently for the same physical delivery — GSIN pushes each sub-lot as its own segment (~3 segments/delivery), UPC merges the whole delivery into one cohort (1 segment/delivery) — so the same `L=3` budget held roughly one delivery's history under GSIN vs. three deliveries' under UPC. GSIN was hitting the truncation continuously; UPC almost never. Dropped lots are always the *stalest*, so GSIN's exported belief was systematically missing its stale tail — this directly explains both the excess W1 error *and* a separately-found positive signed bias (GSIN's belief systematically overestimated freshness, `belief_f − truth_f > 0`, while UPC sat near zero). The same truncated wire also feeds the real controller's effective-inventory calculation (`session.rs`'s `f_belief_for_policy`), so this was under-counting real on-hand inventory under GSIN in production, not just in the diagnostic.

**Secondary, lower-confidence mechanism (documented, not fixed):** GSIN's cross-lot sales-allocation likelihood (`loglik_sales_by_units` / `lot_shares_from_freshness` in `unit_ll.rs`) scores against a **static Multinomial** built from pre-removal picking weights, rather than the true sequential-without-replacement mechanism the simulator actually uses (`pick_units_f` in `day_step.rs`; the codebase already has the exact equivalent scorer, `sequential_kernel_path_logprob`, sitting unused nearby). This is the one stage of GSIN's four-stage scoring pipeline with no UPC analog (cross-lot allocation is new information, not a refinement of an existing UPC term — see `docs/inference/upc-vs-gsin.md`), so it isn't covered by the formal "GSIN ≥ UPC" containment proof. Reasoned mechanism: the static approximation doesn't capture the true process's self-balancing depletion (a fresh lot's *share* of remaining picks declines as it depletes, independent of per-unit weight), so it predicts more extreme fresh/stale splits than actually occur, systematically penalizing particles with real inter-lot differentiation and pulling the posterior toward flatter beliefs than truth. This plausibly explains the *residual* gap that survived both the `L` fix and the replay correction, concentrated specifically in the no-delivery-history contexts. **Not fixed — flagged as real, understood, future work.**

## 3. The fix, applied and verified

- `crates/voi_core/src/params.rs`: `DEFAULT_L_DIM` 10 → 50.
- `src/blueberries_voi/experiments/voi_profit.py`: `profit_session_config`'s explicit `"L": 3` → `50` (this literal override was silently beating the Rust default everywhere in the experiment pipeline; fixing only the Rust constant would have done nothing for any of tonight's figures).
- Benchmarked `L=3,10,20,30` under both `damped_sw` and `sla_pb`: no meaningful runtime difference among 10/20/30 (all comfortably inside Studio's 500ms/1000ms autopilot budgets); `sla_pb` tail latency was actually *worse* at `L=3` (p95 ~88ms vs. ~46ms at L≥10) — no performance reason to pick a small `L`. Chose 50 for headroom given the cost is effectively free.
- Rebuilt and reran `article_figures.ipynb` at `L=50`: ladder chart returned to clean strict monotonicity (GSIN now beats Pack date, as expected); factorial scatter flipped GSIN to performing as well or better than UPC in every delivery-history context (no-delivery-history residual persisted, consistent with the Track-B mechanism above); signed bias reversed from a strong systematic +0.05 to +0.065 to a modest −0.026, in line with other rungs.

## 4. Controller decision

Discovered along the way that `channel_joint.run_seed_channel_joint` (the pipeline behind every closed-loop figure) hardcodes `policy="damped_sw"` via `_damped_sw_act_kw`, regardless of which alpha table entry is loaded — so despite calling it "sla_pb" in conversation for a while (loading alpha from the `"sla_pb"` table entry), every figure has actually always been `damped_sw`. Separately investigated `sla_pb` (Poisson-binomial fast-path SLA controller) vs. `sla_mc` (Monte Carlo oracle): `sla_mc` showed a genuine non-convergence problem (order jumped 16→128 units between 128→256 MC paths on a toy belief) — not trustworthy. Given that, and that `damped_sw` already matches the draft's existing controller-formula prose with zero rewrite needed, **Oliver has now explicitly settled on `damped_sw` only, no SLA controllers, for the post.**
