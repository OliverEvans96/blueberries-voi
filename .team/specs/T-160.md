# T-160 — Studio embed self-contained mount (issue #8)

## Problem

`<Studio />` never initializes when hosts mount into a container other than
`#app`. `StudioProvider` falls back to `document.getElementById("app")` when no
`containerRef` is passed, but `App.tsx` does not pass `containerRef`. Hosts
mounting into any other element get a silent no-op (stuck on Loading).

## Acceptance criteria

### AC-mount

`<Studio />` (via `App`) mounts into a non-`#app` container when `#app` is not
present in the document. After boot, `#section-controls` is in the DOM and the
mount root has `data-studio-init="1"`.

### AC-self-contained

`App.tsx` wires an internal `containerRef` and passes it to `StudioProvider` so
embed consumers do not need a `#app` element.

### AC-diagnostic

`StudioProvider` logs `console.error` when no mount container is found (neither
`containerRef.current` nor `#app`).

### AC-docs

`EMBEDDING.md` documents that the studio is self-contained (no `#app`
requirement) and includes a Vite `optimizeDeps.exclude` section for the dev
pre-bundling trap.

### AC-version

Bump `web/package.json` from `0.3.7` to `0.3.8` and update
`tests/test_studio_release_version.py` accordingly.
