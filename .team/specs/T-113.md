# T-113 Lazy per-scenario filter caches and live obs_scenario

## Context

T-112 capped the studio episode at 90 days and stopped dropping history. Knowledge chips still
stage `obs_scenario` as dirty-until-Reset (ADR 0110). Naive mid-stream retarget of the live
particle cloud is still forbidden. This ticket adds a richest day log plus lazy per-rung
`ResearchParticleFilter` checkpoints and `EngineSession.set_obs_scenario` catch-up so chips retarget belief
(and Autopilot’s next `act`) without resetting physics.

## Acceptance criteria

- [ ] After each Python `advance_day` / `EngineSession.step`, the session keeps a richest
      episode log (not a rolling drop) including at least totals plus `sales_by_lot`,
      `waste_by_lot`, `age_at_receipt`, and `pack_date` when those exist for the day. Thin
      Snapshot `history` / DayDelta `day` chart fields may stay thin.
- [ ] `EngineSession.set_obs_scenario(id)` catch-up-steps only the selected rung: first select
      at day t initializes a new `ResearchParticleFilter` and steps days `0…t-1` with `mask_for(id)` on the
      richest log; switching back steps only `last_synced+1 … now`. It returns a Snapshot (or
      equivalent belief-bearing payload) with `applied_config.obs_scenario` updated **without**
      Reset. Invalid ids raise like `mask_for`.
- [ ] Catch-up vs a filter that had been live the whole episode is CRN-stable (same seed /
      `run_id` / `STREAM_FILTER_RESAMPLE` keyed by day). A golden: replay-from-log matches
      never-switched.
- [ ] `advance_day` / `act` step **only the active** filter; other warmed rungs fall behind.
      Reset / init / seed / physics knobs wipe the richest log and all per-rung caches.
- [ ] Naive retarget of the current particles’ `_obs_scenario` without replay remains forbidden
      (existing mix-likelihood tests stay, or a new test asserts catch-up creates a distinct
      `ResearchParticleFilter` rather than mutating weights in place).
- [ ] HTTP FastAPI session object and Pyodide `session_rpc` forward one RPC/method
      `set_obs_scenario` (no new resource routes required). Do not edit `.github/workflows/`.
- [ ] Studio chips call that method (not `config_dirty` for `obs_scenario` alone). Catch-up
      shows progress / disables chips while running. Autopilot uses the selected rung’s
      `ShelfBelief` for the next `act`; pause during catch-up then resume. Copy: knowledge
      changes what the store sees, so future orders can change.
- [ ] T-089 tests that require `obs_scenario` chip clicks to set `config_dirty` until Reset
      are updated or gated **in this ticket** (supersession of ADR 0110 apply path).

## Out of scope

- Renaming `ResearchParticleFilter` (later ticket). Keep the class name.
- Rust/wasm `set_obs_scenario` (later parity ticket).
- Parallel live filters every day (6× step).
- Editing GitHub Actions YAML.

