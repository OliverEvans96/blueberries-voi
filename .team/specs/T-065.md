# T-065 NumPy sequential-WOR composition DP

## Context

`sequential_wor_composition_probs` implements the exact ADR 0090 pick-loop DP in a
Python-heavy loop and dominates MF wall-clock. ADR 0097 requires a NumPy rewrite of the
**same** recurrence (fixed weights among nonempty cohorts matching `allocate_sales`), with
no public API change and no new runtime deps. Plan:
`.team/plans/M3-exact-ll-speedup.md`; evidence:
`.team/reports/M3-compute-reduction-brainstorm.md`.

## Acceptance criteria

- [ ] `sequential_wor_composition_probs(counts, sales_tot, weights)` keeps the same public
      signature and return type (`dict[tuple[int, ...], float]`); callers
      (`sequential_wor_composition_prob`, `log_p_sales_waste_given_ages`, MF) need no API edits.
- [ ] On small fixed states (hand grids with `L≤3`, modest `n`/`sales_tot`), the NumPy
      implementation matches a frozen pure-Python reference DP (or the pre-rewrite algorithm
      captured in tests) under `np.testing.assert_allclose` with tight rtol/atol (e.g.
      `rtol=0`, `atol=0` on float64 where feasible, else `atol≤1e-15` / documented tol).
- [ ] Empty / boundary cases match today: `L==0`, `sales_tot==0`, `sales_tot` out of range,
      and full stockout composition behavior stay observationally identical to current tests.
- [ ] Recurrence invariant: among nonempty cohorts, pick probabilities use **fixed**
      `weights` (not `remaining * weights`), matching `model.allocate_sales` (regression test
      tying composition probs to the sim pick law on a tiny shelf).
- [ ] Optional within-`mean_field_update` call-level memo of LL/DP is allowed only if
      posteriors remain bit-identical (or allclose at the same tight tol) vs no-memo; if not
      implemented, tests do not require it.
- [ ] `uv run pytest` green for age_likelihood / related tests; **no** new runtime
      dependencies (`pyproject.toml` / `uv.lock` unchanged for numba/cython/etc.).
