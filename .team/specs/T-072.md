# T-072 Vite serve worker+wheel; honor wheelUrl

## Context

The Pyodide worker hardcodes a placeholder GitHub Release URL and ignores
`?wheelUrl=`. Vite does not serve `/packaging/pyodide/worker.js` or a locally
built slim wheel. Local dual-mode needs both (ADR 0108).

## Acceptance criteria

- [ ] `packaging/pyodide/worker.js` uses the `wheelUrl` query param (and/or an
      explicit configure/init `wheelUrl` param) for `micropip.install` when
      present; hardcoded Release URL is fallback only.
- [ ] Vite config serves (or aliases) the worker so a browser request to the
      documented worker URL (default `/packaging/pyodide/worker.js` or an
      equivalent documented path) returns JavaScript (HTTP 200, not 404).
- [ ] Vite serves a locally built slim wheel at a documented URL (e.g.
      `/wheels/*.whl` or path written by `scripts/build_slim_wheel.py` into a
      Vite-visible directory).
- [ ] Studio / `PyodideAdapter` / `createStudioAdapter` can pass a **local**
      `wheelUrl` (via `VITE_PYODIDE_WHEEL_URL` or opts) that reaches the worker;
      tests assert the override is not dropped.
- [ ] Placeholder `github.com/oliver/...` is not the only path for local
      readiness — README or `.team/qa` note documents the local wheel URL
      contract.
- [ ] Automated tests (Python and/or Vitest under `web/`) fail RED until the
      worker honors `wheelUrl` and Vite serve contracts hold.

## Interfaces

- Worker bootstrap: read `self.location.search` / `URLSearchParams` for
  `wheelUrl` (and accept configure/init params if already partially wired).
- Vite: `server.fs.allow` / `publicDir` / middleware / alias as needed so
  worker + wheel are fetchable from the studio origin.
- Env: `VITE_PYODIDE_WORKER_URL`, `VITE_PYODIDE_WHEEL_URL` remain the studio
  contract keys.
