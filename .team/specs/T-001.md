# T-001 Scaffold, package layout, and SIM-05 RNG

## Context

M1 needs an installable package skeleton matching ENG-02 (model/sim/filter/controller/voi/viz) and a
SIM-05 hierarchical RNG before any physics or filter code. This ticket lands stubs, runtime deps per
ADR 0084, and the SeedSequence spawn API so later tickets address randomness by semantic slot.

## Acceptance criteria

- [ ] `src/blueberries_voi/` contains subpackages `model/`, `sim/`, `filter/`, `controller/`, `voi/`,
      and `viz/`, each importable (`python -c "import blueberries_voi.model"` etc. succeeds).
- [ ] `controller/` and `voi/` are stubs only (no M2 controller/VOI logic); importing them does not
      raise.
- [ ] `pyproject.toml` declares runtime dependencies `numpy`, `scipy`, and `matplotlib`; `uv lock`
      / `uv sync` succeeds with those packages importable.
- [ ] Module `blueberries_voi.rng` exposes a SeedSequence-spawn API keyed by at least
      `(run_id, day, stream)` where `stream` includes `:demand`, `:spoil`, `:alloc`,
      `:arrival_ship`, `:arrival_sensor`, and `:filter_resample`.
- [ ] Two independent draws from the same `(run_id, day, stream)` with the same parent seed are
      bit-identical; draws from different streams with the same parent seed differ.
- [ ] Changing the number of draws consumed on stream `:demand` does not change the sequence on
      stream `:spoil` for the same `(run_id, day)` (slot addressing, not call-order addressing).
- [ ] `uv run ruff check .`, `uv run mypy src tests`, and `uv run pytest` pass on the scaffold + RNG
      tests alone after this ticket.
