# T-064 Unique-particle MF dedup in `_particle_filter_update`

## Context

After resampling, many ResearchParticleFilter particles share identical count vectors and age marginals, but
`_particle_filter_update` still calls `mean_field_update` once per particle on the P1/F2a totals path.
ADR 0103 locks exact-faster work: dedup unique `(counts, age_post)` keys, run MF once, broadcast.
See `.team/reports/M3-compute-reduction-brainstorm.md` § Rank 1 / A2 and
`.team/plans/M3-exact-ll-speedup.md`.

## Acceptance criteria

- [ ] On a P1-style update (`backend_name == "mean_field"`, sales/waste totals observed,
      lot maps `UNOBSERVED`), particles with identical fingerprints
      `tuple(counts[i].tolist())` and `age_post[i].tobytes()` receive **identical**
      `age_post` rows after `_particle_filter_update` (exact array equality), matching a naive
      per-particle `mean_field_update` reference on the same inputs.
- [ ] A fixture with **N≥4** particles where at least two share the same `(counts, age_post)`
      key invokes `mean_field_update` **fewer times** than `N` (spy/import call count), and
      the number of calls equals the number of unique keys for that step.
- [ ] A fixture where **all** particles have distinct fingerprints still invokes
      `mean_field_update` once per particle (call count == N); posteriors match the naive loop.
- [ ] Lot-map path (F1/F1s: observed `sales_by_lot` / `waste_by_lot`) is unchanged: MF dedup
      does not run; `_apply_lot_map_age_update` remains the age path (spy/import identity).
- [ ] Public signatures of `mean_field_update` and `_particle_filter_update` callers are unchanged;
      `uv run pytest` covers the new tests; no new runtime deps in `pyproject.toml` / `uv.lock`.
- [ ] ADR **0103** is `STATUS: ACCEPTED` (DATE 2026-08-12).
