# T-161 — Scale-adaptive stratified rollout candidate search

## Problem

Dense ±radius neighbourhood search wastes rollout budget on redundant nearby
case multiples. A fixed-count stratified wide lattice over a scale-adaptive span
covers more of the order space at the same candidate count K.

## Acceptance criteria

- [ ] `candidate_orders_v2(base_q, case_size, &CandidateSearchConfig)` in Rust
      with `Neighborhood` (legacy) and `StratifiedWide` modes.
- [ ] Wide mode: always includes `base_q`; returns K unique case multiples;
      span adapts via `span_fraction` with min/max clamps unless `span_cases` fixed.
- [ ] `candidate_case_radius` alone → neighbourhood mode (unchanged behaviour).
- [ ] Default production path remains neighbourhood until ablation; wide mode opt-in
      via `candidate_search_mode` / `n_candidates` / `candidate_span_cases`.
- [ ] PyO3: optional kwargs `candidate_search_mode`, `candidate_span_cases`,
      `n_candidates` on `rollout_order_py` and `EngineSession.act`.
- [ ] Python mirror in `bakeoff_rollout.py` with tests in `tests/test_rollout.py`.
- [ ] Existing `test_candidate_neighbourhood_is_plus_minus_two_cases` unchanged.

## Defaults

| Knob | Prod | Demo |
|------|------|------|
| `n_candidates` | 5 | 3 |
| `span_fraction` | 0.25 | 0.25 |
| `min_span_cases` | 4 | 4 |
| `max_span_cases` | 10 | 10 |
| `mode` | `neighborhood` | `neighborhood` |
