# T-131 F-native rollout forward-sim parity (Rust primary)

## Context

`crates/voi_core/src/rollout.rs` `path_value_f_belief` is a scaffold (repeat delivery,
fixed demand, hard-coded costs, wrong terminal salvage, no pipeline / schedule / base
continuation). Python structural reference: `src/blueberries_voi/sim/bakeoff_rollout.py`.
Callers: `alpha_tune.rs`, `session.rs`, `voi.rs`.

ADR [0134](../adr/0134-f-native-rollout-forward-sim.md) supersedes the scaffold with
f-native `unit_day_step` forward sim, oracle `truth_f_belief` continuation (no inner
filter), `RolloutContext`, and f-weighted terminal salvage per ADR 0061 in f coordinates.
Cross-refs: ADR 0059, 0061, 0130; T-030 gates (Rust-primary era).

## Acceptance criteria

### Rust forward sim (`crates/voi_core/src/rollout.rs`)

- [ ] **No repeat delivery over H:** With `first_order > 0`, `H ≥ 3`, and empty `pending0`,
      total units delivered across the path equals **`first_order` plus pipeline arrivals
      only** — never `first_order × H`. Verified by a Rust unit test counting
      `deliver_units` / arrival events (fixture: default `OrderSchedule`, `lead_time=1`).
- [ ] **`w_long` terminal `V_T`:** At path end, added terminal value equals
      `margin * effective_inventory_f_belief(lot_counts, f_marginals, f_grid, pending_sum=0)`
      on `truth_f_belief` terminal state; `terminal_salvage_f_belief` documents
      `V_T = m * Σ_l E[f|l] * n_l` (f-native ADR 0061). Rust unit test on a hand-built
      terminal grid with `margin = 2.0`.
- [ ] **Paired CRN rollout ≥ SW:** On a fixed oracle fixture (`truth_f_belief` initial
      belief, `DampedSurvivalWeightedPolicy` base, `DEFAULT_ORDER_SCHEDULE`, smoke
      shipments), mean **path value** of the rollout-selected order is **≥** mean path
      value of the base SW order under paired CRN for `root_seeds = (11, 22, 33)`,
      `H = 28`, `n_rollout_paths ≥ 4`, `candidate_case_radius = 2`, absolute tolerance
      **`1e-6`** (improvement or tie per ADR 0059).
- [ ] **Costs parameterization affects ranking:** For the same belief / CRN fixture, two
      calls to `rollout_order` with identical seeds but `waste_cost` (or `stockout_penalty`)
      differing enough to flip the best candidate **must** return different winning
      `first_order` values. Rust unit test with a small explicit candidate list.
- [ ] **`RolloutContext` wired:** `session.rs`, `voi.rs`, and `alpha_tune.rs` pass
      schedule, pending, day, costs, alpha/rho, shipments, and CRN `run_id` into rollout
      (not the scaffold's bare `rollout_order` literals-only path). `cargo test -p voi_core`
      includes at least one test that `rollout_order` with non-default `waste_cost` changes
      the chosen quantity vs default costs.

### CRN desync gate

- [ ] **`detect_crn_desync` gate:** `tests/test_t131_f_native_rollout.py` (or sibling)
      imports `blueberries_voi.sim.bakeoff_rollout.detect_crn_desync` and asserts
      `ok=True` for matching SIM-05 addresses and `ok=False` when the `stream` label is
      crossed (same pattern as T-030 / `tests/test_m2_gates.py` wiring).

### Rust-primary Python fallback

- [ ] When `blueberries_voi._core` is **built** and `BLUEBERRIES_VOI_BACKEND=rust`,
      `EngineSession.act(policy="rollout")` does **not** import or execute
      `bakeoff_rollout._path_value` (inspect / monkeypatch guard in
      `tests/test_t131_f_native_rollout.py`).
- [ ] When `_core` is **not** built, a documented thin path (e.g. `alpha_tune` /
      `backend.warn_fallback_once`) calls `sim.bakeoff_rollout.rollout_order` without
      raising; test uses `pytest.importorskip` inversion or env guard documented in the
      test module docstring.

    pub margin: f64,
    pub waste_cost: f64,
    pub stockout_penalty: f64,
}

pub fn path_value_f_belief(
    ctx: &RolloutContext<'_>,

    h: u32,

pub fn rollout_order(
    ctx: &RolloutContext<'_>,
    base_q: u32,
    h: u32,

    radius: i32,

pub fn terminal_salvage_f_belief(
    lot_counts: &[f64],
    f_marginals: &[f64],
    f_grid: &[f64],

) -> f64;
