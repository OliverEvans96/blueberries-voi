# T-121 Tier 2 Rust compute parity

## Context

Make `crates/voi_core` the sole hot compute kernel (Tier 2 per ADR 0127). Python
becomes thin PyO3/WASM orchestration; duplicate compute modules are removed in Wave F
after expanded parity tests pass. Milestone spans Waves A–F with max six parallel
implement agents in P2 burst 1; `session.rs` changes serialize on one session-owner.

## Acceptance criteria

### Wave A — wire fidelity and RPC configure

#### A1 — PyO3 wire delegation (`crates/voi_py/src/lib.rs`)

- [ ] **A1:** With `BLUEBERRIES_VOI_BACKEND=rust` and `blueberries_voi._core` importable, `EngineSession.init(...)` returns a Snapshot whose `belief.lot_counts` and `belief.live_lots` are non-empty for the standard smoke config used in `tests/test_rust_session_wire.py` (RED track T-121a).
- [ ] **A1:** Snapshot `seq` equals the session step counter (monotonic across `step` / `act`), not `episode_day`.
- [ ] **A1:** Rust `init` accepts `L`, `K`, and `obs_scenario`; after init, snapshot belief dimensions and observation scenario match the requested values.
- [ ] **A1:** Snapshot includes `applied_config`, `schedule`, and `demand_summary` keys populated to match Python `_coerce_snapshot` backfill semantics (ADR 0100 contract).

#### A2 — RPC init/reset configure (`crates/voi_core/src/session.rs`)

- [ ] **A2:** `handle_rpc` `"init"` and `"reset"` accept nested `config` with fields `shipments`, `lead_time`, `enable_filter`, `n_particles`, `H`, `n_rollout_paths`, `candidate_case_radius`, `L`, `K`, `obs_scenario`; returned snapshot reflects configured `n_particles`, `lead_time`, and non-default shipments (not smoke defaults).
- [ ] **A2:** After configure, `schedule.lead_time_days` equals `self.lead_time` (no drift between schedule wire and session lead time).
- [ ] **A2:** `cargo test -p voi_core` RPC/session unit tests added in T-121a pass for full-config init.

#### A3 — WASM demo hydrate (`packaging/wasm/worker.js`)

- [ ] **A3:** WASM worker `init` sends clamped demo shipments and budget fields equivalent to `prepare_demo_config` in `packaging/pyodide/session_rpc.py` (T-071 parity); init snapshot under WASM reports the same shipment count and lead time as the Pyodide reference fixture in `tests/test_rust_session_wire.py`.

### Wave B — policy engine (belief-based `act`)

#### B1 — `mean_bank` export (`crates/voi_core/src/belief_flat.rs`)

- [ ] **B1:** Public `mean_bank(bank) -> (counts, taus)` returns the same `(counts, taus)` as the private helper used in `voi.rs` for ordering (unit test in `voi_core`).
- [ ] **B1:** When filter is disabled, `mean_bank` yields empty flat belief counts consistent with Python `empty_flat_belief` (zero counts, usable taus grid).

#### B2 — `constant_order` (`crates/voi_core/src/policy.rs`)

- [ ] **B2:** `constant_order(q, case_size)` returns a non-negative integer order quantity that is an exact multiple of `case_size` for representative `(q, case_size)` pairs (Rust unit test).
- [ ] **B2:** `constant_order` differs from `damped_sw_order` on the same belief when `q > 0` and demand quantile would exceed `q` (Rust unit test).

#### B3 — session `act` dispatch (`crates/voi_core/src/session.rs`)

- [ ] **B3:** `EngineSession::act` dispatches `policy` aliases `constant`/`const`/`fixed`, `damped_sw`/`sw`, and `rollout`/`ctl` to the corresponding Rust policy functions using **belief** counts/taus from `mean_bank`, not `self.state.counts` (truth).
- [ ] **B3:** Filter-enabled Rust unit test: when true lot counts differ from belief mean counts, `act(policy="rollout")` order quantity differs from an act that used true counts (regression for truth-vs-belief).
- [ ] **B3:** `act` accepts budget overrides (`alpha`, `rho`, `H`, `n_rollout_paths`, `candidate_case_radius`, `n_particles`, `order_qty`/`q`); overridden `alpha` changes damped_sw order vs default in a Rust unit test.
- [ ] **B3:** `act_rollout()` remains callable as alias for `act(policy="rollout")`.
- [ ] **B3 (concurrency):** B3 and C3 land in one session-owner worktree series — no parallel edits to `session.rs` across agents.

#### B4 — PyO3 and RPC `act` wiring

- [ ] **B4:** Python `EngineSession.act(policy=..., **budgets)` with `BLUEBERRIES_VOI_BACKEND=rust` routes policy and budget kwargs to Rust `act` (T-121b `tests/test_rust_act_policies.py` green).
- [ ] **B4:** WASM/C `handle_rpc` `"act"` accepts `policy` and budget fields in params; response DayDelta `seq` increments and order applied matches Rust `act` for `constant`, `damped_sw`, and `rollout` on a fixed belief fixture.

### Wave C — calendar demand (CAL-01 in Rust)

#### C1 — `demand_profile.rs` (new module)

- [ ] **C1:** `DemandProfile::mu(day)` matches Python `demand_profile.mu(day)` within `1e-9` absolute tolerance for golden days `0`, `6`, `7`, `13`, and `89` (`tests/test_rust_calendar_demand.py`, T-121c).
- [ ] **C1:** `DemandProfile::from_json` parses committed `data/freshnet/demand_profile.json` without error; `cargo test -p voi_core` demand_profile unit tests pass.

#### C2 — `draw_demand` + `ModelParams` (`physics.rs`, `day_step.rs`)

- [ ] **C2:** `ModelParams` carries `demand_profile: Option<DemandProfile>` and `demand_mu_for_day(day)` returns profile-backed μ when set, else legacy constant μ.
- [ ] **C2:** `draw_demand(rng, params, day: Option<u32>)` uses `demand_mu_for_day(day.unwrap_or(0))` when a profile is loaded (Rust unit test: mean of 10_000 draws at day 7 differs from flat-μ draws).

#### C3 — session calendar wire (`session.rs`)

- [ ] **C3:** `advance_one` passes episode day into `draw_demand` when a demand profile is configured.
- [ ] **C3:** `demand_summary_wire` exposes DOW factors from the loaded profile, matching Python `EngineSession` demand summary for the same profile JSON (T-121c comparison test).
- [ ] **C3:** Over a fixed-seed 90-day rust-backend session with FreshNet profile loaded, mean recorded demand differs from the mean obtained with flat μ=30 by more than 1.0 cases/day (`tests/test_rust_calendar_demand.py`).

#### C4 — VOI calendar wire (`voi.rs`)

- [ ] **C4:** `run_voi_crn_cell` episode loop calls `draw_demand` with the episode day index when `ModelParams` includes a demand profile (Rust unit test or Python CRN test showing calendar-sensitive total demand vs flat μ on same seed).

### Wave D — VOI CRN observation ladder

#### D1 — full masks (`voi.rs`)

- [ ] **D1:** `mask_obs` stub removed; each filter step builds `RichDay` and applies `obs::mask_for(scenario).apply(&rich_day)` (T-121d).
- [ ] **D1:** On a fixed CRN seed, scenario `P0` profit ≠ scenario `F1` profit in `run_voi_crn_cell_py` (`tests/test_rust_voi_crn_masks.py`).
- [ ] **D1:** Scenario `F2` path exercises lot-resolved observations (Rust unit test or Python test asserting non-books-only obs fields differ from `P0` on same seed).
- [ ] **D1:** `candidate_case_radius` is read from `CrnBudgets` (not hardcoded `1`); changing radius changes rollout order on a fixed belief fixture (Rust unit test).

### Wave E — parity suite and production default (verifier gate)

- [ ] **Wave E:** Expanded `tests/test_rust_parity.py` covers day_step injected path, one-day filter_step, 10-day EngineSession trajectory with fixed orders, and VOI CRN smoke with seven scenarios showing structural profit differentiation.
- [ ] **Wave E:** Full CI-parity on Python 3.11 (`pip install -e ".[dev]"`, ruff, mypy, pytest with coverage ≥80%) plus `cargo test -p voi_core -p voi_wasm` PASS.
- [ ] **Wave E:** Default `BLUEBERRIES_VOI_BACKEND` is `rust` when env unset (`backend.py`); existing tests that require Python backend set the env explicitly and still pass.
- [ ] **Wave E:** ADR 0127 STATUS updated to ACCEPTED; T-110 backlog follow-on in `.team/backlog.md` line 30 closed or superseded.

### Wave F — Python duplicate removal

#### F1 — thin `session.py`

- [ ] **F1:** `src/blueberries_voi/simulator/session.py` contains no call to Python `day_driver.advance_day` or Python `model.day_step` on the rust backend path (static test or AST scan in Wave F qa).
- [ ] **F1:** With `BLUEBERRIES_VOI_BACKEND=rust`, `tests/test_simulator_session.py` and T-121 wire/act tests remain green without importing deleted modules.

#### F2 — thin `crn.py` + backend default

- [ ] **F2:** `voi/crn.py` public entry loads Abdella shipments when `shipments=None`, resolves alpha table, then delegates episode execution to `run_voi_crn_cell_py` only (no Python episode loop body).
- [ ] **F2:** `backend.py` default backend is `rust`; `warn_fallback_once` emits when `BLUEBERRIES_VOI_BACKEND=rust` and `_core` is missing.

#### F3 — delete duplicate compute modules

- [ ] **F3:** Files removed after F1+F2 merge: `model/physics.py`, `model/day_step.py` compute paths, `filter/rbpf.py`, `filter/particle/counts_update.py` production path, `controller/damped_sw.py`, `controller/rollout.py`, `controller/ordering.py`, `simulator/day_driver.py` — verified absent from `src/blueberries_voi/`.
- [ ] **F3 (guard supersession):** qa updates or gates tests that imported deleted modules in the same milestone — at minimum `tests/test_damped_sw_policy.py`, `tests/test_rollout.py`, `tests/test_t097_act_damped_sw.py`, and `tests/test_voi_crn.py` — so verify pytest collection succeeds without ImportError.
- [ ] **F3:** `BLUEBERRIES_VOI_BACKEND=python` remains testable via retained façades/types for bakeoff diagnostics; full verify suite PASS after deletions.

- PyO3 for Pyodide / `wasm32-unknown-emscripten`.
- Unifying session ceil vs SW nearest case rounding (ADR 0118).
- Editing `.github/workflows/` (human step).
- `VITE_ENGINE_ADAPTER=wasm` prod default (may overlap T-120; human decision).
