# T-158 Sim params right drawer (layout v7)

## Context

Layout v6 keeps the full tuning dock in a bottom cockpit row, which reduces space for
metrics and belief. This ticket moves all tuning clusters into a right-side overlay
drawer opened from a gear icon beside the engine status chip, adopting cockpit grid v7.

## Acceptance criteria

- [ ] **AC-1:** `#linked-charts` has `data-layout="v7"` and grid areas
  `metrics | belief | sidebar` only; no `.cockpit-row--tuning` in the DOM after mount.
- [ ] **AC-2:** Title bar has `.title-bar-actions` with `#tuning-drawer-trigger` (gear)
  immediately left of `#engine-status`; `engineStatus.test.ts` still passes.
- [ ] **AC-3:** `#tuning-drawer-host` exists under `.bv-studio-portal-root`; `TuningDrawer`
  renders a `<dialog id="tuning-drawer">` with `aria-modal`, backdrop close, Escape close,
  and `aria-expanded` sync on trigger (mirror `ReferenceDrawer` tests).
- [ ] **AC-4:** All five tuning sections (Demand, Arrival, Physics, Logistics, Autopilot)
  render controls in `#section-controls` and their `.focus-plot` charts inside the drawer;
  tab clicks switch visible section; `controls.test.ts` mount fixture uses drawer host.
- [ ] **AC-5:** Keyboard shortcuts `1–7` and arrow keys open the drawer when closed and
  activate the matching section; `?` opens ReferenceDrawer only.
- [ ] **AC-6:** Opening tuning drawer closes reference drawer; opening reference closes
  tuning drawer.
- [ ] **AC-7:** On drawer open, active focus plots re-render with non-zero width
  (double-rAF or equivalent); no blank charts after first open.
- [ ] **AC-8:** Drawer body uses 2-column interleaved layout; calendar plot spans full
  width in Logistics; mobile collapses to 1 column below ~600px.
- [ ] **AC-9:** `web/package.json` version is `0.3.6`; `tests/test_studio_release_version.py`
  expects `0.3.6`.
- [ ] **AC-10:** `web/tests/studio-visual-qa.spec.ts` opens drawer via gear before section
  tab assertions; smoke spec expects v7 grid; `pnpm test` and Python 3.11 CI gates pass.

## Out of scope

- Changes to `controls.ts` / `sections.ts` public APIs or chart renderer internals.
- Rust kernel or WASM changes.
- New tuning sections or observation tab revival.
