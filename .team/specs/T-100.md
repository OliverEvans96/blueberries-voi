# T-100 Autopilot play/pause loop

## Context

With `act` policies (T-097) and typed adapters (T-098) plus Controller knobs
(T-099), the studio needs a single-flight wall-clock loop and Play chrome
Autopilot Play/Pause that drives the same DayDelta → ViewModel path as Advance.

## Acceptance criteria

- [ ] Module `web/src/autopilotLoop.ts` exports a start/stop (or play/pause) API
      that: awaits one `adapter.act(opts)`, applies the DayDelta via the existing
      projector path, then schedules the next tick with
      `max(0, intervalMs - elapsed)` and **never** starts a second `act` while one
      is in flight.
- [ ] Default `intervalMs` is **500** when policy is `damped_sw` or `constant`,
      and **1000** when policy is `rollout` (unless the user override from
      Controller interval input is set — user value wins).
- [ ] Play chrome exposes **Autopilot Play** and **Autopilot Pause** (or a toggle
      with those accessible names/labels); starting play runs the loop; pause
      clears the scheduled timer and leaves the session at the last applied day.
- [ ] While Autopilot is running, manual **Advance** is disabled **or** clicking
      Advance performs one manual `step` day and **pauses** Autopilot (pick one;
      document in UI hint). Both behaviors satisfy AC.
- [ ] After each successful Autopilot `act`, the order slider / order inputs sync
      to the last applied `day.order_qty`.
- [ ] Autopilot **pauses** when `config_dirty` becomes true (staged config not
      yet Reset) and when `act` rejects / throws (error surfaced via existing
      studio error reporting).
- [ ] Vitest covers: single-flight (no overlapping act), delay uses
      `max(0, intervalMs - elapsed)` (fake timers), pause on error, pause when
      dirty flag set, order sync from delta.

## Interfaces

### `web/src/autopilotLoop.ts`

```ts
export type AutopilotDeps = {
  act: (opts?: ActOpts) => Promise<DayDelta>;
  applyDelta: (delta: DayDelta) => void;
  getOpts: () => ActOpts;
  getIntervalMs: () => number;
  isConfigDirty: () => boolean;
  onError: (err: unknown) => void;
  onTick?: (delta: DayDelta) => void; // e.g. sync order slider
};

export type AutopilotHandle = {
  play: () => void;
  pause: () => void;
  isRunning: () => boolean;
};

export function createAutopilotLoop(deps: AutopilotDeps): AutopilotHandle;
```

### Play chrome (`web/src/controls.ts` / `main.ts`)

- Buttons or toggle: Autopilot Play / Pause
- Wire `createAutopilotLoop` with live adapter + projector + Controller opts

### Supersession note

Do **not** route Autopilot through `generate.ts` `runDay(..., autopilot)`. That
in-process base-stock flag is not the Autopilot Mode product path (ADR 0117).
Existing tests that only exercise the mock heuristic may remain; new Autopilot
UI tests must call `adapter.act`.
