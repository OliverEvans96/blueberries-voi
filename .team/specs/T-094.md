# T-094 Controller section + order chart

## Context

Autopilot needs visible policy/budget knobs and an order time-series in the
studio. Add section id `controller` (nav key **8**), controls, and a chart,
reusing the inventory-target plot where useful, wired from `main.ts`.

## Acceptance criteria

- [ ] `web/src/sections.ts` includes a section with `id: "controller"`, label
      suitable for nav (“Controller”), and it is the **8th** entry in
      `STUDIO_SECTIONS` (1-based nav key **8** after the existing seven).
- [ ] `SectionId` union includes `"controller"`; `loadSection` / `saveSection`
      accept it; Belief and other sections remain intact.
- [ ] Controller controls in `web/src/controls.ts` (or clearly owned control
      mount used by section controls) expose:
      - policy chips / selector for `damped_sw`, `rollout`, `constant`
      - numeric (or range) inputs for `alpha`, `rho`
      - rollout budget inputs: `H`, `n_rollout_paths`, `candidate_case_radius`,
        `n_particles`
      - interval input (ms) used by Autopilot (T-095 may read the same state)
- [ ] Chart module `web/src/charts/controllerOrders.ts` renders order quantity
      over episode days from ViewModel / day history (`day.order_qty`).
- [ ] Controller `plotIds` include the controller orders plot id and reuse the
      existing inventory target plot id (`plot-inventory`) so operators see
      orders alongside on-hand / target.
- [ ] `web/src/main.ts` mounts the controller chart when that plot is visible
      and wires control changes into studio state (no Python ModelParams mapping
      required — knobs feed ActOpts / Autopilot state only until Reset for
      physics).
- [ ] Vitest covers section registration (`id === "controller"`, nav position /
      length) and at least one chart helper or mount smoke (series from sample
      history).

## Out of scope

- Autopilot play/pause loop (T-095) — may leave interval state ready for it
- Python session policy changes (T-092)
- ActOpts typing (T-093) beyond consuming whatever typed opts already exist
- Mapping Weibull/demand sliders into `ModelParams` on each act
- Merging to `main`
