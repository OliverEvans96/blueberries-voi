# T-074 Studio footer, env defaults, and live-adapter errors

## Context

After hydrate (T-071), Vite/wheelUrl (T-072), and CORS (T-073), the studio UI
still presents “Fake data studio” and may keep placeholder Release URLs. This
ticket aligns footer, env defaults, and user-visible errors with live Http /
Pyodide adapters (ADR 0108).

## Acceptance criteria

- [ ] Studio footer text no longer says **“Fake data studio”** when the selected
      adapter is `http` or `pyodide`; copy reflects live / dual-mode studio
      (exact wording implementer-chosen but must not claim fake/mock).
- [ ] Default / documented local env for HTTP mode uses a localhost API base
      URL compatible with CORS (T-073); for Pyodide mode uses local worker +
      local wheel URLs from T-072 (not only `github.com/oliver/...`).
- [ ] When adapter init/step fails, the studio surfaces an error message to the
      user (non-silent); tests or a small harness assert the error path exists.
- [ ] `MockAdapter` remains available only when explicitly selected
      (`VITE_ENGINE_ADAPTER=mock`); default readiness path does not silently
      fall back to mock.
- [ ] Vitest (and/or focused Python contract tests) cover footer/env selection
      behaviours above.
