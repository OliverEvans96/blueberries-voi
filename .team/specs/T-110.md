# T-110 Rust backend for Python EngineSession

## Context

T-109 ports the interactive driver in `voi_core` and a PyO3 `PyEngineSession`, but
`blueberries_voi.simulator.session.EngineSession` still always runs Python
`advance_day`. Interactive benches with `BLUEBERRIES_VOI_BACKEND=rust` are not
comparable until that façade dispatches.

## Acceptance criteria

- [ ] When `BLUEBERRIES_VOI_BACKEND=rust` and `blueberries_voi._core` imports, `EngineSession.init` / `step` / `step_n` / `reset` / `act` use the Rust session (not `day_driver.advance_day` for those calls).
- [ ] Returned Snapshot and DayDelta dicts still include ADR 0100 keys: Snapshot `seq`, `episode_day`, `belief`; DayDelta `seq`, `episode_day`, `day`.
- [ ] `step_n(orders)` with length k returns k DayDeltas and increments `host_crossings` by exactly 1 (one FFI call).
- [ ] When `BLUEBERRIES_VOI_BACKEND=python` (default), behaviour stays on the existing Python implementation; existing `tests/test_simulator_session.py` still pass.
- [ ] Python `simulator/session.py` is not deleted. Rust still has no Abdella parquet loader.
- [ ] `.team/reports/rust-vs-python-wasm-bench.md` notes that native rust-pyo3 interactive rows can use EngineSession dispatch; Pyodide Node column may stay n/a.

## Out of scope

- Embedding Pyodide in Node; wasm VOI RPC; Abdella parquet in Rust; live GHA YAML; bit-identical RNG.

## Interfaces

Same `EngineSession` methods. Optional `host_crossings()` on the façade when the rust backend is active.
