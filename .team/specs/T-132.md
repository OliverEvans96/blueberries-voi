# T-132 CAL-B4 — Heterogeneous protection demand quantile (MC)

## Context

With calendar demand (ADR 0113 / T-082), protection-window demand is a sum of
**heterogeneous** daily NB draws μ(day+k), not n i.i.d. copies of flat μ.
Controllers already use day-indexed protection **length** (3/3/4); this ticket
upgrades the **quantile** to match calendar μ(day) via Monte Carlo.

Distinct from T-084 (CRN wire). MC seed is a planning constant, not episode CRN.

## Acceptance criteria

- [ ] `protection_demand_quantile(alpha, params, *, protection_days, start_day=0,
      n_mc=20_000, mc_seed=None)` returns the α-quantile of the sum of daily NB
      demands with means μ(start_day+k) when a demand profile is configured.
- [ ] **Fast path (no profile):** behaviour identical to pre-ticket `nbinom.ppf`
      closed form.
- [ ] **Flat-window fast path:** when all μs in the window are equal (within
      tolerance), use closed form without MC.
- [ ] **Heterogeneous MC:** vectorized sum of `NB(μ_k, vm)` replicates;
      discrete empirical quantile (`method="higher"` / ceil index); deterministic
      seed derived from `(start_day, protection_days, alpha)` when `mc_seed` is
      `None`.
- [ ] Python SW controllers pass `start_day=day`:
      `DampedSurvivalWeightedPolicy`, `damped_sw_order_f_belief`, `alpha_tune`,
      `m2_gates` (order-day loop).
- [ ] Rust `protection_demand_quantile` accepts `start_day`; `damped_sw_order_f_belief`
      and `alpha_tune` `protection_target_at_seed` wire `day`.
- [ ] Golden Python–Rust parity on committed `data/freshnet/demand_profile.json`
      for at least one `(start_day, protection_days, alpha)` tuple.
- [ ] Focused pytest RED→GREEN; verifier CI gate PASS on Python 3.11.
