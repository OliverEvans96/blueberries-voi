# T-159 — Notify personal-website when docs-dist publishes

Closes GitHub issue #12.

## Goal

When CI publishes `docs-dist` on a main push, trigger a repository dispatch so
`OliverEvans96/personal-website` redeploys and picks up the latest VitePress
bundle at `/docs/blueberries/`.

## Acceptance criteria

1. **AC-dispatch-step:** The `deploy` job in `packaging/github-workflows/ci.yml`
   has a step named `Notify personal-website to redeploy docs` using
   `peter-evans/repository-dispatch@v3` with `secrets.PERSONAL_WEBSITE_DISPATCH_PAT`,
   repository `OliverEvans96/personal-website`, and event-type
   `blueberries-docs-published`.
2. **AC-step-order:** The dispatch step runs after both `Upload studio dist
   artifact` and `Upload docs dist artifact`.
3. **AC-main-only:** The dispatch step lives only in the existing `deploy` job
   (gated to main/master pushes).
4. **AC-guard-test:** `tests/test_docs_deploy_dispatch.py` asserts the packaging
   canonical YAML contract.
5. **AC-docs:** `packaging/github-workflows/README.md` documents the dispatch
   step and human PAT / sync instructions.

## Implementation notes

- Edit `packaging/github-workflows/ci.yml` only; human syncs to
  `.github/workflows/` via `./scripts/sync-github-workflows.sh`.
- Do **not** add `continue-on-error` on the dispatch step.
- Prerequisites: `docs-dist` upload steps already exist; VitePress `base` is
  `/docs/blueberries/`.

## Out of scope

- Editing live `.github/workflows/`.
- Creating the PAT or wiring the secret in personal-website (human ops).
