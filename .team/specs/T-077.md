# T-077 CAL-A1 — OrderSchedule API

## Context

CAL-01 needs a single tested definition of order weekdays, next-order lookup, and protection
length (3/3/4 on Sun/Tue/Thu) before episode gates or controllers can depend on it. Independent of
FreshNet fit (T-078).

## Acceptance criteria

- [ ] A frozen `OrderSchedule` type is importable from the library (module under Track A ownership
      per ADR 0114 / 0113) with defaults `delivery_weekdays={0,2,4}`, `lead_time_days=1`,
      `order_weekdays={6,1,3}`.
- [ ] `can_order(day)` returns True exactly when `(date(2024,1,1) + timedelta(days=day)).weekday()`
      is in `{6, 1, 3}` for `day` in a multi-week test range (at least days 0..20).
- [ ] For a Sunday order day in the epoch calendar, `protection_days(day) == 3`; for Tuesday, `== 3`;
      for Thursday, `== 4`.
- [ ] `next_order_day(day)` returns the smallest `d > day` with `can_order(d)` (strictly after today);
      e.g. from a Monday non-order day it lands on the following Tuesday order day.
- [ ] `can_order` is False on Mon/Wed/Fri (delivery days under LT=1) and on Saturday.
- [ ] Unit tests fail if epoch weekday alignment drifts (day 0 = Monday 2024-01-01).
- [ ] Public exports / `__all__` (or documented import path) expose `OrderSchedule` without importing
      HF / `datasets` / web modules.
- [ ] `uv run ruff check` and `uv run mypy` on touched paths pass; focused pytest on new tests pass
      with `--no-cov`.

## Out of scope

- Episode / session order gating (T-079)
- Controller protection rewires (T-081)
- FreshNet / demand profile (Track B)
- Web UI

## Interfaces

```text
@dataclass(frozen=True)
class OrderSchedule:
    delivery_weekdays: frozenset[int]  # default {0,2,4}
    lead_time_days: int                # default 1
    order_weekdays: frozenset[int]     # default {6,1,3}

    def can_order(self, day: int) -> bool: ...
    def next_order_day(self, day: int) -> int: ...
    def protection_days(self, day: int) -> int: ...

DEFAULT_ORDER_SCHEDULE: OrderSchedule  # MWF / LT=1 base case
```
