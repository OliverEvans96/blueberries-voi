# T-068 Production filter: arrival-only ages, counts-only PF, exact WOR weights

## Context

ADR 0105 locks production inference to arrival-only effective ages, a counts-only
particle filter with `day_step`-consistent count transitions, and exact sequential-WOR
particle weights (multinomial optional). Today's `_rbpf_update` still uses MC weights,
±1 count RW, and `mean_field_update`. Guard tests encode the old settle and must be
superseded in this ticket before implement.

## Acceptance criteria

- [ ] No production closed-loop path calls `mean_field_update`: AST and/or runtime checks
      cover `RBPF.step` / `_rbpf_update` and thin callers
      (`simulator/day_driver.py`, `sim/m2_multi_scenario.py`, `voi/crn.py`) so that a P1
      step with UNOBSERVED lot maps does not invoke `mean_field_update`.
- [ ] Each live lot’s τ is set at birth from scenario arrival info
      (`delivery_birth_age_prior` / F2 / F2a / cold Abdella) and advanced only by the shared
      MOD-02 / `days_on_shelf` clock — not rewritten by in-store sales/waste LL updates.
- [ ] Default particle weights use exact sequential WOR
      (`log_p_sales_waste_given_ages` / `sequential_wor_*`); a filter config knob
      (e.g. `sales_likelihood`) selects `exact_sequential_wor` by default and may select
      `multinomial` for ablation; production VOI / default `RBPF()` stay on exact WOR.
- [ ] Count transitions match simulator physics (shared allocate/spoil / `day_step`
      kernels), not an independent ±1 random walk on `counts`.
- [ ] **Guard supersessions (qa updates bans in this ticket before implement):**
      - `tests/test_production_mean_field.py` — stop requiring production
        `mean_field_update` / MC-not-WOR weights / `PRODUCTION_BACKEND == "mean_field"` as
        the age-MF settle; replace with ADR 0105 production contracts.
      - `tests/test_age_likelihood.py` — retire
        `test_production_rbpf_update_still_uses_mc_ll` (MC-not-WOR ban); keep diagnostic
        API tests for `mean_field_update` / exact joint as non-production.
      - `tests/test_rbpf_unique_mf.py` — retire or gate unique-MF dedup requirements on the
        production `_rbpf_update` path (MF hot path removed).
      - `tests/test_audit_t044_mf_stubs_hygiene.py` — retire production MF-sweep=5 path
        requirements tied to `_rbpf_update`; keep stub markers / non-MF hygiene that still
        apply.
      - Related locks that still assert production MC weights or production MF backend
        identity (`tests/test_mc_likelihood.py` weight ban, `tests/test_belief.py` /
        `tests/test_filter.py` / M2 closeout `PRODUCTION_BACKEND == "mean_field"` where
        they encode ADR 0091) updated or gated so verifier is not blocked by stale bans.
- [ ] `mean_field_update` / MC LL remain importable for diagnostic/legacy use; tests may
      still exercise them off the production path.
- [ ] Quality gates: focused qa RED with `--no-cov`; implement green with ruff/mypy on
      touched paths; verifier full AGENTS rung once.
