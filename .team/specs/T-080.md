# T-080 CAL-B2 — Fit demand_profile.json

## Context

After ingest/PROVENANCE (T-078), fit a committed DOW×week demand profile scaled to operational μ≈30
for runtime loaders. No physics signature change yet (that is T-082).

## Acceptance criteria

- [ ] A fit script (under `scripts/`, requiring `[freshnet]`) produces `data/freshnet/demand_profile.json`
      committed to the repo (size suitable for git; not raw HF dump).
- [ ] Profile encodes day-of-week × week-index (or month) mean structure plus dispersion / scale
      metadata needed to recover μ(day) at operational scale.
- [ ] Operational mean of the scaled profile is approximately **30** (tolerance documented in fit
      report, e.g. within ±1 or ±5% — pick one and test it).
- [ ] Fit report artifact (markdown or JSON beside the profile) records: SKU IDs selected, censoring
      rule applied (prefer low/zero `stock_hour6_22_cnt`), V/M choice (refit or keep 2.0), and
      Mar–Jun seasonality honesty.
- [ ] `PROVENANCE.md` updated with final SKU ID list and pointers to profile + fit report.
- [ ] Profile schema is versioned (field or filename) so T-082 loader can validate.
- [ ] Running the fit is **not** required for `pytest` on CI without `[freshnet]`; committed JSON is
      the source of truth for tests.
- [ ] No HF import from package runtime modules; ruff/mypy on touched paths pass.

## Out of scope

- Wiring `draw_demand(day=)` / physics (T-082)
- CRN identity regression (T-084)
- Web demand charts (T-087)
- Full two-stage latent demand recovery
