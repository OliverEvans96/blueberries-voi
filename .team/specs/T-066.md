# T-066 Re-benchmark exact LL speedups (P1/F2a)

## Context

After T-064 (unique-particle MF dedup) and T-065 (NumPy sequential-WOR DP), M3 needs
measured speedups vs the pre-change baseline for the exact ADR 0090 path — not surrogate
math. Report lives at `.team/reports/M3-exact-ll-speedup-bench.md`. Motivation and probe
methods: `.team/reports/M3-compute-reduction-brainstorm.md`,
`.team/reports/M3-compute-reduction-plain-language.md`, plan
`.team/plans/M3-exact-ll-speedup.md`. ADR 0097.

## Acceptance criteria

- [ ] `.team/reports/M3-exact-ll-speedup-bench.md` exists and records wall times with
      `OMP_NUM_THREADS=1` (and notes any other thread-limiting env) for at least:
      (a) `sequential_wor_composition_probs` / DP table microbench,
      (b) `mean_field_update` microbench,
      (c) closed-loop **P1** and **F2a** probes (short T / small N acceptable if documented).
- [ ] Report includes **before vs after** (or baseline commit SHA vs post T-064+T-065 tip)
      for those probes, with enough detail to reproduce (seed, N, T, β, scenario, command).
- [ ] Report states whether speedup is from dedup, NumPy DP, or both (ablation or staged
      notes), and that the density remains exact sequential-WOR (no surrogate).
- [ ] A runnable bench entry point exists under `experiments/` or documented
      `uv run python …` commands cited in the report; running the documented command(s)
      produces the tables/numbers without editing library public APIs.
- [ ] Quality gates still green: `uv run ruff check . && uv run mypy src tests && uv run pytest`
      (bench code is not required to be under coverage gates if it lives only under
      `experiments/` / report — but must not break package tests).
