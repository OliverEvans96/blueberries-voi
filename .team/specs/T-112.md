# T-112 Studio episode horizon: full history, cap at day 90

## Context

The studio still keeps a rolling 14-day history window (`_HISTORY_WINDOW` / `window_days` /
`drop_oldest`). Charts and PnL totals therefore show a trailing slice, not the episode. This
ticket drops that window, accumulates days `0…t` until a hard stop at day 90, and prompts Reset.

## Acceptance criteria

- [ ] After more than 14 Python `EngineSession.step` calls (default backend), Snapshot `history`
      and every DayDelta keep all days so far; `drop_oldest` is always `false`; Python does not
      pop old thin-day records.
- [ ] `EngineSession.step`, `act`, and `step_n` refuse when `episode_day >= 90` (before advancing),
      raising a documented error whose message mentions the episode end and Reset. `step_n` that
      would cross the cap refuses without applying a partial prefix.
- [ ] Reset / init clears history and allows a new episode from day 0. Other SimConfig knobs stay
      dirty-until-Reset as today.
- [ ] JS projector and mock adapter append history and never drop until Reset; they do not slice
      to 14. `pnl_totals` and chart series use the full accumulated history. Ghost-vs-last-reset
      compares two full episodes (or the overlapping prefix if the previous run was shorter).
- [ ] Studio UI: at episode day 90, Advance is disabled, Autopilot pauses (or refuses play), and
      copy tells the user the episode finished and they must Reset. PnL labels are episode totals,
      not “Window …”.
- [ ] `window_days` is no longer a user-facing rolling chart knob (default/cap is episode length
      90). Existing tests that encoded 14-day drop must be updated in this ticket.
- [ ] DayDelta still includes the `drop_oldest` key (always false) so ADR 0100 schema tests keep
      that required field.

## Out of scope

- Lazy per-scenario filter caches / `set_obs_scenario` (next ticket).
- Renaming `RBPF`.
- Rust/wasm session cap (later parity ticket). Do not require rust backend behaviour here.
- Editing `.github/workflows/`.

## Interfaces

- Constant (name up to implement): episode length **90**.
- `EngineSession.step` / `act` / `step_n`: raise when already at/past day 90.
- DayDelta: `drop_oldest: false` always on this path.
- UI: Reset remains the only way to start another episode after the cap.

## Open questions

- [x] Exception type: a clear `ValueError` (or existing session error type) with Reset in the
      message is enough; no new HTTP status required this ticket.
