# T-098 Typed ActOpts + adapter normalize + MockAdapter.act

## Context

Autopilot UI must pass a typed policy/budgets object into every engine host.
HttpAdapter nests under `budgets`; PyodideAdapter spreads flat into the worker.
MockAdapter needs a real `act` so Autopilot Play works without Python (heuristic
OK; must document ≠ Python rollout).

## Acceptance criteria

- [ ] `web/src/engine/types.ts` exports a typed `ActOpts` (not only
      `Record<string, unknown>`) with optional `policy` and optional budget
      fields matching ADR 0112 (`alpha`, `rho`, `H`, `n_rollout_paths`,
      `candidate_case_radius`, `n_particles`, `order_qty` / `q`).
- [ ] A shared normalizer (module-local or exported helper) produces:
      - **HTTP body shape:** `{ policy?: string, budgets: Record<...> }` with
        budget knobs nested under `budgets` (no flat `alpha` sibling of
        `policy` in the POST JSON).
      - **Pyodide / flat shape:** `{ policy?: string, alpha?: number, rho?:
        number, H?: number, ... }` suitable for worker `act` params.
- [ ] `HttpAdapter.act` uses the nested shape; `PyodideAdapter.act` uses the flat
      shape; both accept the same caller-facing `ActOpts`.
- [ ] `MockAdapter.act(opts?: ActOpts)` exists, returns a `DayDelta` that advances
      one mock day (seq / episode_day progress like `step`), and chooses an order
      from `opts` (constant/`order_qty`, or a documented heuristic for
      `damped_sw` / `rollout`).
- [ ] Vitest (or existing adapter tests) assert: typed opts compile/use; HTTP
      request body nests budgets; Pyodide call params are flat; MockAdapter.act
      returns DayDelta without forbidden presentation keys.
- [ ] Mock heuristic is documented in a short comment on `MockAdapter.act` (or
      adjacent README/docstring) stating it is **not** numeric-parity with Python
      `rollout_order` / `DampedSurvivalWeightedPolicy`.

## Interfaces

### `web/src/engine/types.ts`

```ts
export type ActPolicyName =
  | "damped_sw"
  | "sw"
  | "rollout"
  | "ctl"
  | "rollout_order"
  | "constant"
  | "const"
  | "fixed";

export type ActBudgets = {
  alpha?: number;
  rho?: number;
  H?: number;
  n_rollout_paths?: number;
  candidate_case_radius?: number;
  n_particles?: number;
  order_qty?: number;
  q?: number;
};

/** Caller-facing opts; adapters normalize for their transport. */
export type ActOpts = {
  policy?: ActPolicyName | string;
  budgets?: ActBudgets;
} & ActBudgets; // flat fields allowed at top level for convenience; normalizer folds them
```

Exact intersection vs nested-only is implementer choice so long as both adapters
accept one documented caller shape and the AC nesting rules hold.

### `web/src/mock/adapter.ts`

```ts
async act(opts?: ActOpts): Promise<DayDelta>;
```

### EngineAdapter

`act?(opts?: ActOpts): Promise<DayDelta>` remains optional on the interface type
but Mock / Http / Pyodide implementations provide it for Autopilot.
