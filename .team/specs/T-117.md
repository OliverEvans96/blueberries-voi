# T-117 Wasm knowledge chips drive particle posterior heatmap

## Context

T-114 wired `set_obs_scenario` catch-up on `voi_core`, but Snapshot `belief` still comes from
physics `live_lots` (`oracle_flat_belief`), `FilterObs` is totals-only (F1–F2 equal P1), and
`filter_step` births arrivals at τ=0. Studio chips already call the RPC; the Belief tab cannot
show a knowledge-rung posterior on the wasm host.

## Acceptance criteria

- [ ] After arrivals, `EngineSession` Snapshot `belief.age_marginals` under **F2** differs from
      **P0** (same seed, same orders). Physics `live_lots` are identical across those two
      snapshots.
- [ ] After arrivals, **F2a** age mass is **narrower** (lower entropy or smaller second moment
      around the mode) than **P1** on the same episode.
- [ ] After a day with positive waste, **P0** vs **P1** particle weights (or `belief.lot_counts`)
      differ; P0 still omits waste from the likelihood.
- [ ] After a day with **uneven** `sales_by` across lots, **F1** posterior differs from **P1**.
- [ ] Catch-up after mid-episode switch to a rung matches a never-switched session on that rung
      (CRN: same seed, day-keyed filter stream). Invalid ids `P2` and `B-state` error like
      Python `mask_for`.
- [ ] `cargo test -p voi_core` covers mask_for / FilterObs / birth priors / `belief_flat` /
      session wiring above. Vitest asserts projector heatmap **density** comes from
      `snapshot.belief` (not from `live_lots` n/τ); changing belief with fixed live_lots
      changes density; changing live_lots with fixed belief does not rewrite age mass.
- [ ] Do not edit `.github/workflows/`. Prefer zero Python production edits.

Scenario field table matches Python ADR 0086 / `mask_for`:

| Id | Present |
|----|---------|
| P0 | arrivals, sales_total |
| P1 | + waste_total |
| F1 | + sales_by_lot, lot_ids_live |
| F1s | + waste_by_lot, lot_ids_live |
| F2a | P1 + pack_date |
| F2 | P1 + maps + age_at_receipt + lot_ids_live |

Birth: P0/P1/F1/F1s sample τ from session shipments mix; F2a Gaussian mean = calendar
transit (`round(delivery_tau)` / `day - pack_date_days`), SD=0.75; F2 Dirac on
`age_at_receipt`. Ages advance by clock only.

RichDay: `sales_by`/`waste_by`/`lot_ids` from `DayStepOut`; `age_at_receipt` =
`delivery_tau` when arrivals>0; `pack_date_days` = `day - round(tau)` on arrival.
