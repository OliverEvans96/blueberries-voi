# T-089 Studio data scenarios (observation ladder wiring)

## Context

Ticket B of the studio knowledge-scenario work: replace fake P0/P1/P2 blur chips with the
settled filter ladder and wire `obs_scenario` through reset/init into `EngineSession` /
`day_driver` via `mask_for` + `rich_obs_from_day_log`. Ticket A owns belief chart rebin /
age-marginal presentation and is out of scope here. ADR **0110**.

## Acceptance criteria

- [ ] Studio observation chips are exactly **`P0 | P1 | F1 | F1s | F2a | F2` in that order**;
      no **P2** chip, type literal, or mock blur branch remains under `web/src/`.
- [ ] Under the chip row, each active (or focused) scenario shows the locked title and
      description:

      | Id | Title | Description |
      |----|--------|-------------|
      | P0 | Books only | Receipts and POS totals only — no daily waste. |
      | P1 | Shrink gun | Adds storewide daily waste totals. |
      | F1 | Lot ID at POS | Sales broken out by lot. |
      | F1s | Lot ID on shrink | Waste broken out by lot. |
      | F2a | Pack date on ASN | Narrows the arrival-age prior only. |
      | F2 | Age at receipt | Measured age at receipt plus rich lot maps. |

      (Observable via DOM / controls unit test: title + description strings present for each id.)
- [ ] TypeScript `ScenarioId` (renamed from `ObsScenario`) equals
      `"P0" | "P1" | "F1" | "F1s" | "F2a" | "F2"`, matching Python
      `blueberries_voi.filter.types.ScenarioId`. `SimConfig.obs_scenario` uses that type;
      default remains **`P1`**.
- [ ] Changing an observation chip (or other staged `SimConfig` knobs that already dirty)
      sets `ViewModel.config_dirty === true` until **Reset** (or cold `init`) applies config;
      Advance alone does not clear dirty or re-apply a newly selected scenario.
- [ ] `main.ts` Reset / bootstrap **pass the staged config** into `adapter.reset(config)` /
      `adapter.init(config)` (not bare `reset()` / `init()`). Belief-chart mounting code is
      not rewritten in this ticket.
- [ ] `EngineSession.init` / `reset` read `config["obs_scenario"]` (default `"P1"` when
      omitted), store it, echo it on Snapshot `applied_config["obs_scenario"]`, and pass it
      into `advance_day`. Invalid ids raise (same spirit as `mask_for` unknown-key failure).
- [ ] With filter enabled, `day_driver.advance_day` **does not construct `P1Obs`**. It builds a
      DayLog-shaped richest observation (lot maps from `sales_by_cohort` / `waste_by_cohort`,
      `age_at_receipt` / `pack_date` when a delivery exists — pattern of `sim/episode.py`) and
      calls `rbpf.step(rich_obs_from_day_log(day, mask_for(obs_scenario)), ...)`.
- [ ] Mask behaviour is observable on the interactive path: for the same physics seed/day,
      `mask_for("P0")` yields `waste_total is UNOBSERVED` while `mask_for("P1")` presents
      waste; `mask_for("F1")` presents `sales_by_lot`; `mask_for("F1s")` presents
      `waste_by_lot`; `mask_for("F2a")` presents `pack_date` when receipt meta exists;
      `mask_for("F2")` presents `age_at_receipt` and lot maps when those fields exist on the
      day. Hidden fields are never invented as `0` / `{}`.
- [ ] HTTP and Pyodide adapters forward `obs_scenario` inside the config object on init/reset
      (no new routes). Mock adapter / generate accept the six ids and drop P2.
- [ ] SCN-P2 stays **Out**: no new `P2` ScenarioId, no `mask_for("P2")`, no reopen of ADR 0022;
      existing “do not reopen SCN-P2” backlog / plan language remains consistent.
- [ ] This ticket does **not** change belief chart rebinning, age-marginal plot layout, or
      Ticket A chart APIs (no edits required to chart rebin helpers for ACs to pass).

## Interfaces

### TypeScript (`web/src/types.ts`)

```ts
export type ScenarioId = "P0" | "P1" | "F1" | "F1s" | "F2a" | "F2";

export type SimConfig = {
  // ...
  obs_scenario: ScenarioId; // default "P1"
  // ...
};
```

`ObsScenario` is removed (or re-exported as a deprecated alias only if a one-release shim is
needed; prefer delete + fix call sites in this ticket).

### Studio controls (`web/src/controls.ts`)

- Chip row ids: `P0`, `P1`, `F1`, `F1s`, `F2a`, `F2`.
- Description region under chips shows locked title + description for the selected scenario.
- Chip click → `onConfigChange({ obs_scenario })` (stage only).

### Studio wiring (`web/src/main.ts`)

```ts
adapter.init(stagedConfig);   // bootstrap
adapter.reset(stagedConfig);  // Reset button — applies dirty config
```

Do not remount / rewrite belief chart plumbing beyond passing config.

### Python session / day driver

```python
# EngineSession._apply_config
obs_scenario: ScenarioId  # from config.get("obs_scenario", "P1")

# EngineSession._applied_config includes:
{"obs_scenario": obs_scenario, ...}

# day_driver.advance_day(..., obs_scenario: ScenarioId = "P1")
# when enable_filter and rbpf is not None:
day_like = ...  # richest DayLog-shaped object/namespace
obs = rich_obs_from_day_log(day_like, mask_for(obs_scenario))
rbpf.step(obs, step_rng)
```

Richest day fields (when available): `sales_by_lot`, `waste_by_lot`, `age_at_receipt`,
`pack_date`, live lot ids — same mapping as `sim/episode.py` from
`sales_by_cohort` / `waste_by_cohort` + delivery receipt meta.

### Hosts

- `HttpAdapter` / `PyodideAdapter`: pass `obs_scenario` in `config` on init/reset (existing
  ASGI body shape `{ config, seed? }`).
- Mock: drop P2; accept `ScenarioId` for any remaining blur/demo helpers.

### Tests (qa → implement)

- Session / day_driver: mask + richest fields + no `P1Obs` construction on interactive path.
- Studio: chip ladder + locked copy; config passed on reset/init; dirty-until-reset;
  default P1; no P2.
