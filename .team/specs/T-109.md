# T-109 Like-for-like Rust CRN cell and EngineSession driver

## Context

T-108's `run_voi_crn_cell` was a constant-order stub (~0.1 ms). This ticket ports the
**algorithm** from `voi/crn.py` (shared physics, scenario masks, damped-SW + rollout,
shipment ages, scored profit) and EngineSession `advance_day` so smoke/interactive
benches are comparable. RNG is still not NumPy-identical (ADR 0119).

## Acceptance criteria

- [ ] `run_voi_crn_cell` in Rust accepts shipments (times/temps), `n_burn`, `n_score`, `filter_n`, `H`, `n_rollout_paths`, `lead_time`, `alpha`; returns 7 scenario keys; B-state uses oracle counts; others call `filter_step` with masked sales/waste.
- [ ] Arrival age integrates Q10 along injected shipment paths (smoke-cool fixture in tests).
- [ ] Scored profit uses SIM-01 formula on days after burn-in; `cargo test` smoke cell wall time is not treated as a speedup vs Python in comments.
- [ ] `EngineSession` `step` / `act(rollout)` apply order-schedule gate, optional ResearchParticleFilter, rollout; `step_n` is one host crossing.
- [ ] Python `run_voi_crn_cell(..., shipments=, filter_n=, H=)` dispatches to `_core` with those args when `BLUEBERRIES_VOI_BACKEND=rust`.
- [ ] Browser harness times wasm `init`/`step`/`step_n(7)`/`act`; pyodide n/a only if the worker cannot load; report updated.
- [ ] Python modules not deleted. Rust tests cover mask P0 vs P1, empty shipments error, schedule `can_order`.
