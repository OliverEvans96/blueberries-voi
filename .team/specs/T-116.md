# T-116 Missed sales store chart

## Context

The store stack shows units sold and spoilage but not lost sales, even though
`Day.stockout` is already on the wire. This ticket adds a red **Missed sales**
bar chart immediately under Units sold so stockouts are visible in the same
linked hover as the rest of the store.

## Acceptance criteria

- [ ] In `web/src/main.ts` `.chart-stack`, captions/containers appear in this
      order: Units sold (`#chart-sales`) → **Missed sales** (`#chart-stockout`)
      → Lots (`#chart-history`) → Units spoiled (`#chart-spoil`). Caption text
      for the new chart is exactly `Missed sales` (`cd web && npm test` / DOM
      fixture of the store markup).
- [ ] `renderMarginal(..., "stockout")` draws `.bar.bar--stockout` from
      `history[i].stockout` (lost sales). Bars grow **up** like sales (`y =
      yScale(v)`, `height = innerH - yScale(v)`), not down like spoilage.
      Bottom margin matches sales (no `.axis-x` on stockout; spoilage still has
      `.axis-x`).
- [ ] CSS defines `--missed` / `--missed-strong` (red). `.bar--stockout` uses
      `--missed`; `.bar--stockout.bar--active` uses `--missed-strong`. Store
      legend includes a **Missed** chip with class `chip-missed` alongside
      Sales / Lots / Spoilage (`web/src/styles.css` + markup).
- [ ] Sales and stockout charts share one y-domain: `max(sales_total,
      stockout)` over the window, and ghost `series[].stockout` when a ghost is
      passed. `renderStore` computes that max via `marginalYMax` and passes the
      same `yMax` into both `renderMarginal` calls. A fixture where max
      stockout > max sales makes sales bars shorter than they would be on a
      sales-only domain.
- [ ] With `ghost` set, stockout draws `.bar-ghost` from
      `ghost.series[].stockout` (same bar inset as spoilage ghosts) using
      **upward** geometry like sales. Spoilage ghost overlay from
      `series[].waste` is unchanged.
- [ ] `applyHoverStyles` calls `setMarginalHover(els.stockout, day)` in
      addition to sales and spoil. Hovering a day adds `bar--active` /
      `day-hit--active` on the stockout chart for that day (`cd web && npm
      test`).
- [ ] Demand section **Sales vs demand** (`renderSalesDemand` /
      `#chart-sales-demand`) is unchanged: still a line/gap chart, not this
      bar chart.
- [ ] No production edits under `src/blueberries_voi/`, `crates/`, or WASM
      adapters; `package.json` / lockfile unchanged (no new npm deps). No new
      public Python module.

## Out of scope

- Python/API/wire/`Day` schema changes (`stockout` already exists)
- Demand Sales vs demand chart
- New npm deps / new public Python modules / ADR
- Merging to main

## Interfaces

Extend `web/src/charts/marginals.ts` only (no new package):

```ts
export type MarginalKind = "sales" | "spoilage" | "stockout";

export function marginalYMax(
  history: Day[],
  ghost?: EpisodeGhost | null,
): number;
// max(1, max sales_total, max stockout, max ghost.series[].stockout if ghost)

export function renderMarginal(
  container: HTMLElement,
  history: Day[],
  kind: MarginalKind,
  height?: number, // default 72; spoil stays 86 at call site
  ghost?: EpisodeGhost | null,
  yMax?: number, // shared domain for sales + stockout
): void;

export function setMarginalHover(
  container: HTMLElement,
  hoveredDay: HoverDay,
): void;
```

When `kind === "sales"` or `"stockout"` and `yMax` is passed, use it as the
linear domain max (still clamp with `Math.max(1, yMax)`). Spoilage may omit
`yMax` and keep today’s per-chart max of `waste_total` / ghost waste.

`web/src/main.ts`: `els.stockout` → `#chart-stockout`; `renderStore` passes
shared `yMax` to sales and stockout; ghost to stockout like spoil.

Data: existing `Day.stockout` and `GhostSeriesPoint.stockout`. No wire change.
