# T-148 — Real studio version bumps + immutable studio-v* tags

Closes GitHub issue #9.

## Goal

Make the embeddable studio package version meaningful and publish immutable
`studio-v{semver}` GitHub releases alongside the moving `studio-latest` prod
tarball.

## Problem

`web/package.json` has stayed at `0.1.0` across every `studio-latest` rebuild.
The versioned tarball filename on the moving release does not provide immutability
because both assets are overwritten on each publish. Downstream consumers cannot
tell whether they fetched a stale CDN copy or a new fix.

## Acceptance criteria

1. **AC-version-guard:** If any publishable path changes vs merge-base
   (`origin/main` or `GITHUB_BASE_REF`), `web/package.json` `version` must
   strictly increase (semver compare).
2. **AC-first-bump:** Version becomes `0.1.1` for this ticket.
3. **AC-immutable-release:** On `workflow_run` (main CI green), the release job
   publishes `studio-latest` **and** creates `studio-v{version}` when that tag
   is absent.
4. **AC-immutable-assets:** `studio-v*` releases attach only the versioned
   tarball (`oliverevans96-blueberries-voi-studio-{version}.tgz`), **not**
   `-latest.tgz`.
5. **AC-docs:** Update `EMBEDDING.md` and `packaging/README.md` to document
   auto-cut immutable tags and the version-bump policy.

## Publishable paths

Changes under these paths require a semver bump:

| Path | Role |
|------|------|
| `web/src/` | React studio source |
| `web/vite.lib.config.ts` | Library build config |
| `web/scripts/` | Lib asset copy / pack helpers |
| `crates/voi_core/` | Rust simulation kernel |
| `crates/voi_wasm/` | WASM bindings |
| `scripts/build-wasm.sh` | WASM build entry |

## Implementation notes

- Guard test: `tests/test_studio_release_version.py` — git diff vs merge-base.
- Workflow edits: `packaging/github-workflows/release-studio.yml` only (human
  copies to `.github/workflows/`).
- `studio-latest` keeps both versioned tgz + `-latest.tgz` alias.
- `studio-v*` tag push path: versioned tarball only, `make_latest: false`.
- Auto `studio-v{version}` on workflow_run: versioned tarball only,
  `make_latest: false`, skip if tag exists.

## Out of scope

- Editing live `.github/workflows/` (human `sync-github-workflows.sh` step).
- npm registry publish.
- Retroactive `studio-v0.1.0` tag.
