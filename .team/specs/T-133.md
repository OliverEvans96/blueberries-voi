# T-133 — Typed Rust demand profile for alpha_tune

## Context

T-132 added calendar-aware `protection_demand_quantile` in Rust and a JSON-string
PyO3 shim. Notebook 12 and `alpha_tune.py` still skip the Rust kernel when
`params.demand_profile` is set because `evaluate_alpha_tune_outcomes_py` uses
`ModelParams::default()` with no profile wire.

This ticket exposes a **typed** PyO3 `DemandProfile` class (no JSON on the hot
path) and threads it through `evaluate_alpha_tune_outcomes_py` and
`protection_demand_quantile_py`.

## Acceptance criteria

- [ ] `DemandProfile::from_parts(scale_target_mu, dow_factors, week_factors, demand_vm)`
      in `voi_core` with existing validation.
- [ ] PyO3 `#[pyclass] DemandProfile` on `blueberries_voi._core` with `mu(day)`.
- [ ] `evaluate_alpha_tune_outcomes_py` accepts `demand_mu`, `demand_vm`, `case_size`,
      optional `demand_profile`; passes built `ModelParams` to `run_alpha_tune_episode`.
- [ ] `protection_demand_quantile_py` accepts `demand_profile: Option[DemandProfile]`
      instead of JSON string.
- [ ] `alpha_tune._evaluate_via_rust_kernel` converts Python dataclass → `_core.DemandProfile`
      and **removes** the calendar skip guard.
- [ ] `test_alpha_tune_calendar_rust.py`: `mu` parity + Rust vs Python episode outcomes
      with FreshNet profile.
- [ ] `test_protection_quantile_mc.py` parity uses typed profile.
- [ ] Notebook 12 wording updated: Rust path works with calendar demand.
- [ ] Verifier CI gate PASS on Python 3.11.
