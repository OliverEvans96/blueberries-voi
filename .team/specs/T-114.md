# T-114 Rust/wasm `set_obs_scenario` parity

## Context

T-113 added Python `EngineSession.set_obs_scenario`, HTTP, Pyodide RPC, and studio
chips. T-113 explicitly left Rust/wasm out of scope. This ticket wires the same
catch-up protocol through `voi_core` `EngineSession`, wasm/PyO3 RPC, the wasm
adapter, and the mock 90-day refuse.

## Acceptance criteria

- [ ] `voi_core::EngineSession::set_obs_scenario` catch-up-steps only the selected
      rung: first select at day t initializes a new `ParticleBank` and steps days
      `0…t-1` with scenario-masked `FilterObs` on the richest log; switching back
      steps only `last_synced+1 … now`. Snapshot `applied_config.obs_scenario`
      updates without Reset. Invalid ids error like Python `mask_for`.
- [ ] Catch-up vs a filter that was live the whole episode is CRN-stable (same
      seed / day / filter stream). Golden: replay-from-log matches never-switched;
      switch-back is gap-only (no full replay).
- [ ] `step` / `act` step only the active bank; Reset/init wipe the richest log
      and rung caches. Naive in-place weight retarget remains forbidden.
- [ ] `handle_rpc` and `packaging/wasm/worker.js` dispatch `set_obs_scenario`
      like init/step/reset/act. PyO3 `PyEngineSession` exposes the same method.
- [ ] `WasmAdapter` forwards `set_obs_scenario` (same RPC name as Pyodide).
- [ ] Mock adapter `step`/`act`/`step_n` refuse at episode day 90 with a Reset
      message, matching Python `EPISODE_HORIZON`.
- [ ] Do not edit `.github/workflows/`. Do not rename `RBPF`.

## Out of scope

- Renaming `RBPF`.
- Lot-resolved F1/F2 likelihood in Rust (totals-only `FilterObs` masks are enough).
- Merging to `main`.
