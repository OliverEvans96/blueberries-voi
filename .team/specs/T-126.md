# T-126 Studio cockpit redesign — command bar, two-pane grid, self-sized rail, two bugfixes

## Context

A post-T-124 UX review (live screenshots at 1440x900 + Playwright interaction testing against
`./scripts/studio.sh --wasm`) found the ADR 0128 three-zone grid squeezes charts — the studio's
entire value proposition — into the smallest elements on the page, and surfaced two interaction
bugs. This ticket implements the approved remediation: a horizontal chapter tab bar, a two-pane
content grid, a self-sized decision rail, one consolidated reference drawer, a floating day-inspector
tooltip, tabbed store charts, and both bugfixes — **JS/CSS only**, no Python/wire changes. Authority:
ADR [0128](../adr/0128-studio-ux-information-architecture.md),
[0129](../adr/0129-studio-cockpit-redesign.md).

Concurrency plan: [T-126-concurrency.yaml](../plans/T-126-concurrency.yaml). Each AC section below
maps 1:1 to a shard in that plan (`hatch`, `obschip`, `tabs`, `refdrawer`, `dayinspector`,
`storetabs`, `merge`); the six component/bugfix sections are scoped strictly to that shard's own
files and are testable as isolated component/unit tests with no dependency on `studioLogic.ts`
internals. `merge` is the only section allowed to touch `StudioLayout.tsx`, `studioLogic.ts`,
`chapters.ts`, and the master `styles.css`.

## Acceptance criteria

### AC-hatch — `.chart-unavailable-hatch` no longer blocks clicks

Files: `web/src/react/ChartUnavailable.tsx`, `web/src/styles.css`.

- [ ] `.chart-unavailable` (the rule governing `ChartUnavailable.tsx`'s root element) declares
      `position: relative`, so `.chart-unavailable-hatch`'s `position: absolute; inset: 0` is scoped
      to its own box instead of the nearest positioned ancestor up the DOM tree.
- [ ] `.chart-unavailable-hatch` declares `pointer-events: none` in addition to its existing
      `aria-hidden="true"`, so the decorative overlay can never intercept pointer events even if a
      future refactor removes the positioned ancestor again (defense in depth — the two fixes are
      independently sufficient, but both are required).
- [ ] `ChartUnavailable`'s rendered DOM structure, `data-plot-id`, `data-unavailable="true"`,
      `role="img"`, and `aria-label` are unchanged (no regression to `web/src/react/chartSlots.ts`
      consumers or existing `data-unavailable-hatch` marker).
- [ ] Regression test (new `web/src/react/ChartUnavailable.test.ts`, jsdom, RTL) renders
      `<ChartUnavailable plotId="..." caption="..." />` standalone and asserts, via reading
      `web/src/styles.css` source text (`node:fs` `readFileSync`, matching this repo's existing
      pattern in e.g. `web/src/main.stockout.test.ts`), that the `.chart-unavailable {…}` rule block
      contains `position: relative` and the `.chart-unavailable-hatch {…}` rule block contains
      `pointer-events: none`.

### AC-obschip — observation-ladder chip active state stays in sync

Files: `web/src/engine/projector.ts`.

- [ ] `ViewModelProjector.patchEngineState(snapshot)`, when `snapshot.applied_config?.obs_scenario`
      is present, updates `this.config.obs_scenario` to that value (in addition to its existing
      `this.appliedConfig` merge) **before** rebuilding and returning the `ViewModel`. The
      `ViewModel.config.obs_scenario` on the object returned by that single `patchEngineState` call
      must already equal the new scenario — no second, separately-captured `setConfig` call is
      required to observe the correct value.
- [ ] This fix does not change `configsEqual`'s existing behavior of excluding `obs_scenario` from
      `config_dirty` computation (obs-ladder switches remain "live catch-up", not
      dirty-until-Reset — see `web/src/studioObsScenarioCaches.test.ts` T-113 precedent).
- [ ] `patchEngineState` continues to leave `this.config` untouched for every field *other than*
      `obs_scenario` when `applied_config` carries other keys (no widening of what this method
      applies to `this.config`).
- [ ] Regression test (new `web/src/engine/projector.obsScenarioSync.test.ts`): construct a
      `ViewModelProjector`, apply an initial snapshot with `obs_scenario: "P0"`, then call
      `patchEngineState({ ...minimal required Snapshot-picked fields, applied_config: { obs_scenario:
      "F2" } })` and assert the **immediately returned** `ViewModel.config.obs_scenario === "F2"`
      (i.e. the test must not itself call `setConfig` to make the assertion pass — that would mask
      the original bug). Cover at least one other rung transition (e.g. `P1` → `F1s`) and confirm
      `config_dirty` stays `false` across the switch when no other config field changed.

### AC-tabs — `ChapterTabs` horizontal command bar

Files: `web/src/react/ChapterTabs.tsx` (new), `web/src/styles/chapterTabs.css` (new).

- [ ] Exports `ChapterTabsProps = { activeSection: SectionId; onSelectSection: (id: SectionId) =>
      void }` and a `ChapterTabs(props)` component, importing `STUDIO_CHAPTERS` from
      `web/src/chapters.ts` and `STUDIO_SECTIONS` from `web/src/sections.ts` directly (no props
      needed for that static data — matches `DecisionRail.tsx`'s existing pattern of importing
      `OBS_LADDER_IDS`/`SCENARIO_COPY` directly).
- [ ] Renders as a single horizontal row: one `<nav role="tablist" aria-label="Studio sections">`
      containing exactly `STUDIO_SECTIONS.length` (8) elements with `role="tab"`, one per section, in
      `STUDIO_SECTIONS` order — not stacked as a vertical list of chapter blocks.
- [ ] Sections remain grouped by chapter: each chapter (`Operate` / `Understand` / `Tune`) renders a
      distinguishable label/group wrapper (e.g. `data-chapter={chapter.id}`) around its member tabs,
      matching `chapterForSection` groupings; removing the DOM chapter-label nodes must not be
      possible without removing at least one chapter's grouping element per `STUDIO_CHAPTERS` entry
      (3 groups).
- [ ] Each tab displays its 1-based keyboard-shortcut index (matching current
      `.section-nav-index` behavior: `STUDIO_SECTIONS.findIndex(...) + 1`), the section's `label`,
      and its `blurb` (may be visually de-emphasized/hidden except for the active tab, matching
      existing `.section-nav-blurb` show-when-active behavior — carry that behavior forward, do not
      show all 8 blurbs at once).
- [ ] The tab matching `activeSection` has `aria-selected="true"`; all others `aria-selected="false"`.
      Clicking a non-active tab calls `onSelectSection` exactly once with that tab's `SectionId`.
      Clicking the already-active tab does not throw and may re-invoke `onSelectSection` (component
      does not need to suppress redundant calls — that's the caller's concern).
- [ ] `ChapterTabs` does not attach any global `keydown` listener and does not import from
      `studioLogic.ts` — keyboard shortcuts 1–8/arrows remain owned entirely by `studioLogic.ts`'s
      existing global listener (merge task's concern, not this component's).
- [ ] Regression test (new `web/src/react/ChapterTabs.test.ts`, jsdom, RTL): render standalone with
      mock `activeSection`/`onSelectSection` (`vi.fn()`); assert tab count, grouping, index badges,
      `aria-selected` state, and click-to-callback wiring per the bullets above.

### AC-refdrawer — consolidated `ReferenceDrawer`

Files: `web/src/react/ReferenceDrawer.tsx` (new, replaces `GlossaryDrawer.tsx` + `ShortcutHelp.tsx` +
`VoiReferencePanel.tsx`, which are deleted by this shard), `web/src/styles/referenceDrawer.css` (new).

- [ ] `ReferenceDrawer()` is a self-contained component (no required props, matching the existing
      self-contained pattern of the three components it replaces) that renders three trigger buttons
      — "Glossary", "VOI reference", "Shortcuts" — and, when open, exactly one drawer/dialog element
      containing a `role="tablist"` with three `role="tab"` entries (Glossary / VOI reference /
      Shortcuts) and a content panel for the active tab. At most one open dialog/drawer element
      exists in the DOM at any time regardless of which trigger was clicked.
- [ ] Clicking any of the three triggers opens the drawer with that trigger's tab active; clicking a
      tab inside an already-open drawer switches content without closing the drawer.
- [ ] Glossary tab content includes all current `GLOSSARY_ENTRIES` terms verbatim (the "Observation
      scenario" intro entry, one entry per `ScenarioId` in `["P0","P1","F1","F1s","F2a","F2"]` sourced
      from `SCENARIO_COPY`, "Sim truth overlay", and "Base-stock") — no entries dropped or reworded.
- [ ] Shortcuts tab content includes all current `SHORTCUTS` entries verbatim (`1–8`, `← →`, `↑ ↓`,
      `?`, `T`) — no entries dropped.
- [ ] VOI reference tab preserves `VoiReferencePanel`'s existing behavior: fetches `/voi-reference.json`
      on first open (or on mount — either is acceptable as long as it does not fetch before the tab
      has ever been shown, or fetches once and caches; test must cover both the success path

      "VOI reference data not available" note), matching `VoiReferenceData`'s existing shape.
- [ ] Pressing `?` anywhere outside an `INPUT`/`TEXTAREA` opens the drawer on the Shortcuts tab (or
      toggles it closed if already open on that tab) — same guard/behavior as current `ShortcutHelp`.
      Pressing `Escape` closes the drawer regardless of which tab is active.
- [ ] `GlossaryDrawer.tsx`, `ShortcutHelp.tsx`, and `VoiReferencePanel.tsx` are deleted; no other file
      outside this shard's file list imports them (that is `merge`'s obligation to satisfy — this
      shard just needs to not leave dangling exports other files still expect without `merge`
      updating those call sites, see AC-merge).
- [ ] Regression test (new `web/src/react/ReferenceDrawer.test.ts`, jsdom, RTL, with `global.fetch`
      mocked for the VOI-reference cases): standalone render, cover open/close, tab switching, `?`

### AC-dayinspector — floating hover tooltip

Files: `web/src/react/DayInspector.tsx`, `web/src/hoverLink.ts`, `web/src/styles/dayInspector.css`
(new).

- [ ] `web/src/hoverLink.ts` exports a new `HoverPoint` type (`{ clientX: number; clientY: number } |
      null`) and changes `LinkedHoverHandlers` to `{ onDay: (day: HoverDay, point: HoverPoint) => void
      }`. `attachLinkedHover`'s `pointermove` handler, whenever it resolves a `day`, calls
      `handlers.onDay(day, { clientX: event.clientX, clientY: event.clientY })`; its `pointerleave`
      handler (root-exit case, unchanged trigger condition) calls `handlers.onDay(null, null)`. This
      is a breaking signature change for `onDay`'s one existing caller (`studioLogic.ts`) — updating
      that call site is `merge`'s job (see AC-merge), not this shard's.
- [ ] `dayFromClientX` and all other exports of `hoverLink.ts` are otherwise unchanged (no regression
      to existing day-resolution math or margin constants).
- [ ] `DayInspectorProps` becomes `{ day: number | null; point: HoverPoint; vm: ViewModel }`.
      `DayInspector` renders `null` (nothing) when `day == null` or `point == null` — there is no more
      permanent/idle placeholder block (that "Hover a day…" empty state is retired; the header's
      static "Hover a day to highlight it everywhere" hint text elsewhere in the shell is unaffected
      and out of scope for this component).
- [ ] When both `day` and `point` are provided, `DayInspector` renders a small floating element
      (`role="status"`, retains `data-day={day}`) whose inline `style` positions it using
      `point.clientX`/`point.clientY` (e.g. `left`/`top`, or a `transform: translate(...)`) — the
      rendered element's positioning style must be derived from the given `point` values, verifiable
      by rendering with two different `point` values and asserting the resulting inline style differs
      accordingly.
- [ ] Content shown when a day is present is unchanged from current behavior: `Day {day}`, `Sales`,
      `Waste`, `Stockout`, `Order qty` from the matching `vm.history` row, the `beliefOneLiner(vm)`
      one-liner, and the existing "no history yet" fallback text when `day` is provided but no
      matching `vm.history` row exists.
- [ ] Regression tests (new `web/src/react/DayInspector.test.ts` and `web/src/hoverLink.test.ts`,
      jsdom for the former, node or jsdom for the latter, RTL for the component): `DayInspector.test.ts`
      covers the null-render idle case and the positioned-tooltip case with mock `vm`/`point`;
      `hoverLink.test.ts` constructs a fake `PointerEvent`-like object (or dispatches a real
      `PointerEvent` in jsdom) and asserts `onDay` is invoked with `(day, { clientX, clientY })` on
      move and `(null, null)` on leave.

### AC-storetabs — `StoreChartTabs` for the four store charts

### AC-merge — integration: two-pane grid, self-sized rail, component wiring

Files: `web/src/react/StudioLayout.tsx`, `web/src/styles.css`, `web/src/react/studioLogic.ts`,
`web/src/chapters.ts`.

- [ ] `web/src/styles.css` defines the new two-pane layout's base (non-media-query) grid rule with
      exactly two content tracks (Store, Focus) plus a self-sized rail area — this replaces
      `.studio-layout--three-zone`'s three-track definition. `StudioLayout.tsx` no longer references
      `.studio-layout--three-zone` or the three-zone grid class name.
- [ ] The rail's grid-cell selector does not stretch to the height of the Store/Focus tracks: the
      base grid rule either omits `align-items: stretch` for that layout, or the rail-column selector
      explicitly sets `align-self: start` (or `height: max-content` / equivalent) — verifiable via a
      source-text assertion against `web/src/styles.css` — **and** `DecisionRail`'s own `position:
      sticky` behavior (`web/src/react/DecisionRail.tsx` / `.decision-rail` rule) is preserved
      unchanged.
- [ ] At `max-width: 1100px`, the layout collapses to a single column (same breakpoint value as ADR
      0128 / current code) with the rail's container ordered/positioned after both content panes (not
      interleaved between them) — matching or extending the existing `.decision-rail-column { order:
      3 }` pattern under the equivalent new class name.
- [ ] At `max-width: 720px`, the same single-column collapse holds; neither content pane nor the rail
      introduces `overflow: hidden` clipping on `.shell.studio` or the new grid container that would
      break scrolling to any panel's content.
- [ ] `StudioLayout.tsx` no longer imports or renders `GlossaryDrawer`, `ShortcutHelp`, or
      `VoiReferencePanel`; it imports and renders `ReferenceDrawer` exactly once (header-mounted, per
      ADR 0129 §5).
- [ ] `StudioLayout.tsx` no longer renders the old vertical `.section-nav` markup; it mounts
      `ChapterTabs` (statically embedded or dynamically mounted via `createRoot` — either is
      acceptable) wired so that `activeSection` reflects `studioLogic.ts`'s `activeSection` state and
      selecting a tab drives the same code path as today's `setSection(id)`.
- [ ] The four store chart hosts (`#chart-sales`, `#chart-stockout`, `#chart-history`, `#chart-spoil`)
      are wrapped in `StoreChartTabs` (`salesView` = sales + stockout hosts, `ageView` = history +
      spoil hosts) without changing any of the four ids, so `studioLogic.ts`'s existing
      `document.querySelector('#chart-...')` lookups and `renderStore()` continue to work unmodified.
- [ ] `studioLogic.ts`'s hover wiring is updated to the new `hoverLink.ts` signature: `onHoverDay`
      (or its caller) now receives and forwards a `HoverPoint`, and `renderDayInspector()` passes that
      point through to `DayInspector`'s `point` prop. `#day-inspector-host` no longer renders a
      permanent visible block when idle (verifiable: after `onHoverDay(null, null)`, the mounted

- [ ] Guided Paths is promoted to a single header-level entry point (no longer rendered inline inside
      every section's focus pane via `<div id="guided-paths-host">` on every render) — the per-section
      repeated Guided Paths block is removed from `StudioLayout.tsx`'s static focus-pane JSX.
- [ ] No regression to existing keyboard shortcuts: pressing `1`–`8` still calls the equivalent of
      `setSection` for the matching `STUDIO_SECTIONS` entry; `ArrowLeft`/`ArrowUp` and
      `ArrowRight`/`ArrowDown` still cycle sections; `?` now opens `ReferenceDrawer`'s Shortcuts tab
      (superseding the deleted standalone `ShortcutHelp`); `Escape` still closes whatever
      drawer/dialog is open. All four behaviors are exercised by existing or updated tests in
      `web/src/sections.controller.test.ts` / `web/src/main.stockout.test.ts` /
      `web/src/studioScenarios.test.ts` (update those files' assertions in this shard if their current
      assertions reference deleted markup/classes — e.g. `.section-nav-item`, `GlossaryDrawer`,
      `ShortcutHelp`, `VoiReferencePanel` — so they keep passing against the new components; do not
      delete their underlying behavioral assertions).
- [ ] All six observation-ladder scenarios (`P0`, `P1`, `F1`, `F1s`, `F2a`, `F2`) remain selectable
      via the decision rail's obs chips post-merge, and the visibly active chip matches
      `vm.config.obs_scenario` immediately after each switch (this rides on `impl-obschip`'s
      `projector.ts` fix landing first per the concurrency plan's `deps`; this AC is the
      integration-level confirmation that nothing in the merge re-introduces the stale-chip bug, e.g.
      by re-adding an uncaptured `projector.setConfig(...)` call as the *only* source of truth for a
      new code path).
- [ ] The `.chart-unavailable` positioning fix from `impl-hatch` and the `patchEngineState` sync fix
      from `impl-obschip` are both present unmodified in the final tree (no accidental revert during

## Out of scope

- Python, WASM, Pyodide, or Snapshot/DayDelta wire protocol changes.
- Any new npm/Cargo dependency (no floating-UI/positioning library, no new chart library — D3 stays).
- URL routing / deep links.
- SCN-P2 seventh rung.
- Live/citeable VOI computation — `ReferenceDrawer`'s VOI tab keeps the existing static
  `voi-reference.json` stub + disclaimer behavior verbatim.
- New browser/E2E test tooling (the 1440x900 Playwright pass that informed this ticket's diagnosis
  was a one-off manual UX review, not a new CI gate); pixel-accurate visual regression coverage is not
  a requirement of this ticket — automated coverage is component/unit + CSS-source-text level only.
- Recalibrating the 1100px/720px responsive breakpoint *values* (kept from ADR 0128) — only what
  renders at each tier changes.
- Persisting `StoreChartTabs`' active-view selection across reloads (ephemeral UI state is
  sufficient; no new `localStorage` key required, unlike `sections.ts`'s `SECTION_STORAGE_KEY`).
- Editing `.github/workflows/`.
