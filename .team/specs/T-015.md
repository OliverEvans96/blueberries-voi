# T-015 Dynamic L + joint→sliding_window fallback

## Context

ADR 0089 keeps full_joint while `joint_state_count(K,L,N) ≤ MAX_JOINT_FLOATS`, and auto-falls back
to `sliding_window` with a logged reason when long-dwell L would trip the budget — never silent L
truncation (FIL-13).

## Acceptance criteria

- [x] RBPF (or factory) selects **`full_joint`** when `joint_state_count(K, L, N) ≤ MAX_JOINT_FLOATS`.
- [x] When L would exceed the budget, backend becomes **`sliding_window`** and a structured log /
      return field records `{K, L, N, joint_floats, backend="sliding_window", reason=...}`.
- [x] Attempting to **silently truncate** L to fit budget is impossible on the production path; tests
      assert L used equals requested/empirical L (or fallback backend), never a quietly smaller joint
      L.
- [x] Dynamic L: filter track length follows live / configured max cohorts under joint when within
      budget (no permanent hard-code that ignores measured L when safe).
- [x] Short bakeoff / note addendum under `experiments/` documents re-measured L under M2.5
      open-loop and at least one long-dwell cell, plus fallback behaviour.
- [x] FIL-12=B is not reopened; sliding_window is explicitly the FIL-13 fallback.
- [x] Quality gates green.

## Out of scope

- Reopening FIL-12 toward mean-field as default
- Changing `MAX_JOINT_FLOATS` without ADR
- Multi-rung Stage A (T-016) beyond enabling long-dwell cells to run
