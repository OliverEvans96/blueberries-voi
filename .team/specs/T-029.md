# T-029 CTL-03 α fractile tuning

## Context

CTL-03=B requires simulation-tuned α for **every** ladder arm. Untuned α must not be used for ladder
profit claims (hard gate before T-032).

## Acceptance criteria

- [ ] A tuning entrypoint searches α on a documented grid **per ladder arm** (constant, Rung 0, SW,
      and placeholders for rollout/DP arms as available) under shared CRN across α candidates.
- [ ] Tuned α values are written to an artifact under `experiments/` and/or `figures/m2/` (path
      documented in README or module docstring).
- [ ] A test (or harness assertion) **fails** if a ladder profit-claim path is invoked without a tuned
      α table present / loaded (untuned path rejected).
- [ ] Objective uses T-025 day/episode profit (SIM-01=B), not waste-only.
- [ ] No matplotlib inside `controller/`; figure/MD writers live under `experiments/` / `viz/` /
      `figures/m2/`.
- [ ] `uv run pytest` for automated portions passes (grid may be tiny in CI).

## Out of scope

- Full VOI sweep axes (M3)
- Publishing final ladder profit narrative (T-032)
- Browser budgets

## Interfaces

```text
tune_alpha_grid(arm_id, *, alphas, root_seed, ...) -> float  # best alpha
# plus load/save of tuned table artifact
```
