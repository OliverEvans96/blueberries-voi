## Non-blocking

- **T-134 `delivery_f` guards (pre-existing, out of T-138 scope):** `session_passes_precomputed_delivery_f` and `voi_passes_precomputed_delivery_f` still fail because `session.rs:351` and `voi.rs:297` pass `delivery_f: None` while computing `f_at_receipt`. Rollout and `alpha_tune` already pass `delivery_f: f_at_receipt`. These guards existed RED on main (ADR 0138 / T-134); they will fail `cargo test -p voi_core t134_arrival_f` until T-134 lands, but are not T-138 acceptance criteria.
- **CRN scheme split:** session/voi use legacy numeric `stream_rng(…, 7)` while rollout/alpha_tune/Python use `SpawnRng(…, ":birth")`. Within-lot draws are isolated from ship/sensor streams on truth paths, but cross-path bit parity is not guaranteed — consider unifying on `SpawnRng` in a follow-up.
- **AC-9 behavioural gap:** add a rollout unit test with non-degenerate marginal + fixed seed showing two units in the same lot differ.
- **`unit_day_step` fallback:** when `rng_birth` is `None`, dispersion draws use `Pcg64::seed_from_u64(0)` — document or require caller wiring (production paths now pass birth RNG).

## Correctness / security

No secrets or unsafe patterns observed. Main correctness risks are CRN stream coupling on the filter birth block and truth/filter `delivery_f` mismatch in session/voi (T-134), which can desynchronize observed lot-mean freshness from simulated segment mean when dispersion is off.
